# 이슈 등록

규칙 원문은 CLAUDE.md(규칙: "직접 지시 경로") 6번과 "이슈 양식"이다.

## 순서 (작업 단위마다)

1. 초안을 `{{ISSUES}}/.drafts/<이름>.md`에 Write로 쓴다. 양식은 규칙: "이슈 양식" 그대로다. 근거 칸에 지시 원문, 가정, 허용된 조언 요지와 64자리 해시를 적는다.
2. `node {{HARNESS}}/operator/route-issue.mjs --draft <이름>.md`로 라우팅한다.
   - 종료 코드 0이 아니면 이슈를 올리지 말고 알린 뒤 멈춘다. 6(Jev 호출 실패)은 스크립트가 이미 2회 다시 부른 뒤라 다시 부르지 않는다.
3. 출력의 `워커 모델:`, `유형:`, `난이도:` 세 줄을 초안의 `## 영역, 워커 모델, 유형` 절에 **그대로** Edit로 옮긴다. 내가 고르지 않는다.
4. 먼저 끝나야 할 단위가 있으면 `## 의존하는 이슈`에 그 이슈 번호만 적는다(설명 없이).
4-1. 제안문 단위의 `담당 팀`을 초안의 `- 담당 팀: <값>` 줄에 그대로 옮긴다(`dev`, `design`, `tester`, `plan`, `sec`). 단위에 팀이 없거나 다섯 값이 아니면 그 단위는 올리지 않고 같은 조언 id로 어드바이저에게 되돌린다(결정 8-29).
5. `gh issue create --repo {{REPO}} --title "<제목>" --body-file <초안> --label 진행중`으로 올린다. 라벨이 없다고 거부되면 라벨 없이 올린다.

## 확인할 점

- 단위 하나 = 이슈 하나. 구현 방법과 순서는 적지 않는다.
- `공개 가능:`은 애매하면 `아니오`다.
- 앞 단위의 이슈 번호를 알아야 뒤 단위의 의존 칸을 채울 수 있으니 의존 순서대로 올린다.
