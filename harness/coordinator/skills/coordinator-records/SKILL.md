# 기록, 보존 노트, 컴팩션 복구

규칙 원문은 CLAUDE.md(규칙: "기록 문서", "컴팩션과 보존 노트", "선호")다.

## 기록 문서 `{{ISSUES}}/records/{{PROJECT}}.md`

1. 적는 시점: 정리본 승인 요청, 예외 보고(한도 초과·진행 불가), 최종 보고. 질문과 답변은 적지 않는다.
2. 보내기 전에 "전달 예정"을 적고, 다음 대화가 시작되면 그 항목을 "전달 확인"으로 바꾼다.
3. `git -C {{ISSUES}} add records/{{PROJECT}}.md` → `commit -m "<메시지>"` → `push`를 하나씩 실행한다.

## 보존 노트 `{{ISSUES}}/records/{{PROJECT}}-보존.md`

1. 보존 항목이 생기거나 철회될 때마다 **바로** 적는다(컴팩션은 언제든 올 수 있다): 사용자의 명시적 지시와 제약, 확정된 결정과 이유, 바뀐 파일 경로와 식별자(이슈·하달 번호, 해시), 미해결 오류의 핵심, 남은 작업, 승인 대기 항목.
2. 바뀐 항목은 이전 것에 "철회됨"을 붙인다. 끝난 것은 정리한다. 비밀값은 적지 않는다.
3. 기록 문서처럼 커밋·푸시한다.

## 컴팩션 뒤

1. 알림을 보면 보존 노트와 기록 문서를 다시 읽는다.
2. 보존 항목이 모두 남았는지 대화와 맞춰 본다. 못 찾은 것은 추측으로 채우지 않는다.
3. 사용자에게 하는 다음 답을 이 셋 중 한 줄로 시작한다: `컴팩션 복구: 완료` / `컴팩션 복구: 일부 누락 — <빠진 항목>` / `컴팩션 복구: 복구 실패 — <이유>`. 보존 노트 파일이 없으면 `컴팩션 복구: 일부 누락 — 보존 노트 없음`.

## 선호

- 사용자가 직접 말한 소통 선호(출력 양식, 보고 상세도, 질문 빈도, 말투, 승인 방식)는 바로 `{{ISSUES}}/records/preferences.md`에 저장한다.
- 내가 추론한 선호는 같은 요청이 3번째 나올 때 제안 / 이유 / 예상 결과로 제안하고, 승인받은 뒤에만 저장한다.
