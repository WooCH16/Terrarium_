# 조언 받기

규칙 원문은 CLAUDE.md(규칙: "직접 지시 경로") 4~5번이다.

## 순서

1. **조언 id 정하기:** `adv-<지시를 나타내는 영문 한두 단어>-<번호>`(영문 소문자·숫자·붙임표). `{{RUN}}/advice-log.jsonl`을 Read해 이미 쓴 id는 피한다(파일이 없으면 처음). 같은 지시의 조언을 다시 받을 때만 같은 id를 쓴다.
2. **패널로 부르기 (결정 8-24):** 모두 Agent 도구, `subagent_type: advisor`. 패널 폴더는 `{{RUN}}/reviewer-inbox/panel/<조언 id>`다. 세 자리 호출은 한 번에 나란히 보내도 되고 차례로 보내도 된다.
   1. **초안 (3번 호출):** 자리 a, b, c마다 넘긴다: `패널 단계: 초안`, `자리: <a|b|c>`, `패널 폴더: <경로>`, 사용자 지시 원문, 대상 프로젝트 경로 `{{MEMO}}`, (있으면) 조사 결과 파일 경로. **조언 id는 넘기지 않는다**(세 자리가 같은 제안문 파일과 판정 한도를 다투지 않게). 돌아오는 줄은 `초안: <경로>`다.
      - 한 자리라도 `자료 요청:`을 돌려주면 3번의 자료 요청처럼 조사를 하달하고, 답 파일 경로를 넣어 초안부터 다시 한다(1회).
      - 아무것도 돌려주지 않은 자리는 한 번 다시 부른다. 그래도 초안이 둘보다 적으면 패널을 그만두고 예전처럼 어드바이저 하나에 조언 id를 넘겨 부른다.
   2. **교환 (3번 호출):** 자리마다 `패널 단계: 교환`, `자리`, `패널 폴더`, 세 초안의 경로를 넘긴다. 돌아오는 줄은 `추천: <a|b|c> | <이유>`다. 초안 본문은 읽지 않는다.
   3. **세기 (결정 8-26):** 자기 자리를 추천한 줄은 세지 않는다. 그 자리를 한 번 다시 불러 다른 자리를 고르게 하고, 그래도 자기 자리면 그 표는 버린다. 남은 표에서 두 표 이상 받은 자리가 뽑힌다. 셋이 모두 다르면(순환) 자리 a의 추천을 따른다(초안을 읽지 않고 정하는 규칙). a는 자기를 고를 수 없으므로 b나 c가 된다. 그 밖에 뽑힌 자리가 없으면 자리 a의 추천을 따르고, a의 표가 버려졌으면 남은 표 하나를 따른다. 표가 하나도 남지 않으면 자리 a의 초안을 쓴다.
   4. **최종 (1번 호출):** `패널 단계: 최종`, 조언 id, 뽑힌 초안 경로, 다른 두 초안 경로, 사용자 지시 원문, 대상 프로젝트 경로를 넘긴다. 이 어드바이저만 제안문을 쓰고 조언 판정을 받는다.
   - 패널은 조언 한 번에 어드바이저 호출이 7번 든다. 거부되면 최종 어드바이저가 한 번 고쳐 다시 받는다. 패널을 다시 돌리지 않는다.
3. **돌아온 줄 보기 (최종 호출의 결과):**
   - `리뷰어 판정: 허용 | ...` → 4번.
   - `자료 요청: <영역> / <질문>` → `coordinator-research`로 조사를 하달하고, 결과가 오면 같은 id로 다시 부른다.
   - 거부가 두 번이거나 종료 코드 7 → `advice-log.jsonl`의 해시와 거부 이유로 사용자에게 제안 / 이유 / 예상 결과로 묻고 멈춘다.
   - 보고 없이 끝남 → 같은 지시와 같은 id로 다시 부른다(2회까지, 규칙: "실패").
4. **허용 확인:** 셋 다 맞아야 쓴다.
   - 허용 줄의 `조언 id:`가 내가 넘긴 id다.
   - `advice-log.jsonl`에서 그 `sha256` 줄이 `"verdict":"허용"`이다.
   - 그 줄의 `adviceId`가 내가 넘긴 id다.
5. 이슈 근거로 쓰는 것은 `{{RUN}}/handoffs/advice-<해시 앞 8자리>.md`와 64자리 해시뿐이다. 다음은 `coordinator-issues`.

## 확인할 점

- 조언 판정(`run-reviewer --advice`)은 어드바이저가 띄운다. 내가 띄우지 않는다.
- 제안문이 부족한지는 내가 따로 판단하지 않는다. 부족함은 조언 판정의 거부로만 다룬다.
- 하나라도 맞지 않으면 이슈를 올리지 말고 사용자에게 알린다.
