# 조언 받기

규칙 원문은 CLAUDE.md(규칙: "직접 지시 경로") 4~5번이다.

## 순서

1. **조언 id 정하기:** `adv-<지시를 나타내는 영문 한두 단어>-<번호>`(영문 소문자·숫자·붙임표). `{{RUN}}/advice-log.jsonl`을 Read해 이미 쓴 id는 피한다(파일이 없으면 처음). 같은 지시의 조언을 다시 받을 때만 같은 id를 쓴다.
2. **어드바이저 부르기:** Agent 도구, `subagent_type: advisor`. 넘기는 것: 사용자 지시 원문, 대상 프로젝트 경로 `{{MEMO}}`, 조언 id, (있으면) 조사 결과 파일 경로.
3. **돌아온 줄 보기:**
   - `리뷰어 판정: 허용 | ...` → 4번.
   - `자료 요청: <영역> / <질문>` → `coordinator-research`로 조사를 하달하고, 결과가 오면 같은 id로 다시 부른다.
   - 거부가 두 번이거나 종료 코드 7 → `advice-log.jsonl`의 해시와 거부 이유로 사용자에게 제안 / 이유 / 예상 결과로 묻고 멈춘다.
   - 보고 없이 끝남 → 같은 지시와 같은 id로 다시 부른다(2회까지, 규칙: "실패").
4. **허용 확인:** 셋 다 맞아야 쓴다.
   - 허용 줄의 `조언 id:`가 내가 넘긴 id다.
   - `advice-log.jsonl`에서 그 `sha256` 줄이 `"verdict":"허용"`이다.
   - 그 줄의 `adviceId`가 내가 넘긴 id다.
5. 이슈 근거로 쓰는 것은 `{{RUN}}/handoffs/advice-<해시 앞 8자리>.md`와 64자리 해시뿐이다. 다음은 `coordinator-issues`.

## 확인할 점

- 조언 판정(`run-reviewer --advice`)은 어드바이저가 띄운다. 내가 띄우지 않는다.
- 제안문이 부족한지는 내가 따로 판단하지 않는다. 부족함은 조언 판정의 거부로만 다룬다.
- 하나라도 맞지 않으면 이슈를 올리지 말고 사용자에게 알린다.
