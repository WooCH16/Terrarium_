# 판정

규칙 원문은 리뷰어 규칙(규칙: "하는 일", "코드가 먼저 보는 것", "결정", "Jev 질문")이다. **질문 문장은 리뷰어 규칙의 `## Jev 질문` 절에만 있다.** 코드가 그 절을 읽으므로 여기에 옮겨 적지 않는다.

## 결과 보고서 (`run-reviewer.mjs --issue <n>`)

1. 이슈 본문의 완료 기준 표와 가장 최근 `## 결과 보고서` 댓글을 읽는다.
2. **코드 검사:** 첫 줄, `커밋 해시:` 한 줄, 네 칸, `| 기준 | 충족 | 근거 위치 |` 표에 이슈 기준이 글자 그대로 있는지, 근거 위치의 파일이 그 커밋에 있는지. 어긋나면 Jev를 부르지 않고 거부한다.
3. 기준 한 줄마다 `met`, `evidence` 질문을 Jev에 묻는다.
4. 모두 예(`jev.yes` 이상)일 때만 허용한다. 아니오나 애매가 하나라도 있으면 거부이고, 그 질문과 확률이 이유다.
5. 판정을 이슈 댓글로 남긴다. 허용 댓글은 `## 리뷰어 판정: 허용`과 `허용된 커밋: <40자리>` 한 줄이다.

## 제안문 (`run-reviewer.mjs --advice <파일> --advice-id <id>`)

1. 같은 조언 id의 판정 횟수를 `advice-log.jsonl`에서 센다. 2번을 넘으면 판정하지 않고 종료 코드 7.
2. **코드 검사:** `## 작업 단위` 절마다 정해진 칸, `| 기준 | 확인 방법 |` 표, 빈칸.
3. 기준 한 줄마다 `decidable`, `checkable` 질문을 묻는다.
4. 결정 규칙은 결과 보고서와 같다. 허용이면 제안문을 `handoffs/advice-<해시 앞 8자리>.md`로 옮기고 해시를 기록한다.

## 판정하지 않는 경우

- Jev 호출이 실패하면(종료 코드 6) 판정하지 않는다. 실패를 거부로 읽지 않는다.
- 판정하는 동안 제안문이 바뀌면 결과를 인정하지 않는다(종료 코드 4).
