# 조언 패널

규칙 원문은 어드바이저 정의(규칙: "입력 (코디네이터가 넘긴다)", "할 일", "제안문 양식")다. 같은 어드바이저 정의를 세 번 불러 세 자리(a, b, c)로 쓴다. 자리끼리는 직접 말할 수 없으므로 파일로 초안을 나눈다. 코디네이터는 초안을 읽지 않고 추천 줄만 센다.

## 자리마다 보는 관점

| 자리 | 먼저 보는 것 |
|---|---|
| a | 작업 단위 나누기: 단위 크기, 파일·관심사 경계, 먼저 끝나야 할 것 |
| b | 전제·위험: 잘못된 전제, 빠진 고려, 분야 지식(`advisor-domain-knowledge`)으로 짚을 점 |
| c | 완료 기준: 관찰할 수 있는 결과인지, 확인 방법이 그 줄만으로 실행되는지, 주관적 목표가 대리 기준으로 바뀌고 원래 목표가 "전제·위험"에 있는지(결정 8-27) |

관점은 출발점일 뿐이다. 초안은 어느 자리든 "제안문 양식" 전체를 채운다.

## 단계

1. **초안** (`패널 단계: 초안`, `자리: <a|b|c>`, `패널 폴더: <경로>`):
   - 대상 프로젝트를 읽고 자기 관점에서 제안문을 "제안문 양식" 그대로 쓴다.
   - `<패널 폴더>/<자리>.md`에 Write로 쓴다. 다른 곳에는 쓰지 않는다.
   - **판정 명령을 실행하지 않는다.** 조언 id도 받지 않는다.
   - 돌려주는 것은 `초안: <파일 경로>` 한 줄뿐이다. 제안문을 쓸 수 없으면 `자료 요청: <영역> / <질문>` 한 줄을 돌려준다.
2. **교환** (`패널 단계: 교환`, `자리`, `패널 폴더`):
   - 다른 두 자리의 초안을 Read로 읽는다. 대상 프로젝트를 다시 읽어 서로 어긋나는 주장을 확인한다.
   - 다른 초안에서 맞는 점을 받아들여 자기 초안 `<패널 폴더>/<자리>.md`를 고친다.
   - **다른 두 자리 가운데** 그대로 판정에 올리기 더 좋은 초안을 하나 고른다. 자기 초안은 추천할 수 없다(결정 8-26). 다른 초안의 좋은 점은 위처럼 자기 초안을 고치는 데 반영한다. 기준은 단위를 작은 모델이 이슈 글만 보고 끝낼 수 있는가, 완료 기준을 그대로 확인할 수 있는가(주관적 목표가 기준에 남아 있으면 확인할 수 없다), 지시에 없는 일을 더하지 않았는가 순서다.
   - 돌려주는 것은 `추천: <다른 자리> | <이유 한 줄>` 한 줄뿐이다(자리 a는 b나 c, b는 a나 c, c는 a나 b).
   - **판정 명령을 실행하지 않는다.**
3. **최종** (`패널 단계: 최종`, 조언 id, 뽑힌 초안 경로, 다른 두 초안 경로):
   - 뽑힌 초안을 바탕으로, 다른 두 초안에서 빠진 위험이나 확인 방법이 있으면 더한다. 단위를 새로 늘리지 않는다.
   - 결과를 `{{RUN}}/reviewer-inbox/<조언 id>.md`에 쓰고, 그다음은 규칙 "할 일" 4~6번 그대로 판정을 받는다. 거부되면 고쳐서 한 번만 다시 받는다(`advisor-proposal`).
   - 돌려주는 것은 지금처럼 판정 스크립트의 출력 줄이다.

## 하지 않는 것

- 초안·교환 단계에서 `{{RUN}}/reviewer-inbox/` 바로 아래에 파일을 쓰거나 `run-reviewer.mjs`를 실행하지 않는다. 판정 횟수 한도(조언 id마다 거부 2번)는 최종 단계만 쓴다.
- 패널 폴더의 초안을 지우지 않는다(어드바이저에게는 지우는 도구가 없다). 코디네이터에게 초안 본문을 돌려주지 않는다.
