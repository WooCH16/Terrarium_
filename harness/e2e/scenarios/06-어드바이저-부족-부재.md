# 시나리오 6: 어드바이저 부족·부재

overview 9절 시나리오 6의 대본이다(T12, 이슈 #15). 통과 조건은 산출물로 적고, 산출물로 볼 수 없는 것은 "직접"(사용자가 직접 보고 확인한다)으로 표시한다.

## 사용자 입력 원문

- (가) memo 목록에 정렬 옵션을 추가해 줘. [부족]
- (나) 별도 실행 폴더에서: memo 목록에 정렬 옵션을 추가해 줘.

## 대역 설정

(가) `setup --advisor-stub`, 지시 끝의 `[부족]`으로 대역이 부족한 제안문을 낸다. (나) `issues/advisors.md`를 `stubs/advisors.empty.md`로 바꾼 별도 실행 폴더. 검사는 (가)만 자동이다.

## 수치 경계

- 코디네이터 세션 실행: 최대 2번
- 하달(run-operator): 최대 0번
- 조언 판정: 같은 조언 id로 최대 2번(첫 제출 + 수정 1회, 소유자 결정 8-2)
- 재작업: 이슈당 2회까지, 3번째에 막힘(이슈 #2 결정 2-1)

## 통과 조건

`node harness/e2e/verify.mjs --scenario 6 --run <실행 폴더> --since <시작 시각>`이 "자동" 줄을 검사한다. `--dry`는 검사 항목만 나열한다. 산출물 칸의 첫 `` `...` ``가 검사식이다(쉼표로 여럿).

| 검사 | 확인 | 산출물 |
|---|---|---|
| (가) 같은 조언 id로 거부가 2번 기록됐다 | 자동 | `advice:거부 = 2` |
| (가) 허용 없이 이슈가 없다 | 자동 | `issues = 0` |
| (가) 2번째 거부 뒤 사용자에게 제안 / 이유 / 예상 결과로 물었다 | 직접 | 세션 출력 |
| (나) 어드바이저를 부르지 않고 이슈 없이 즉시 보고했다 | 직접 | (나) 실행 폴더의 `guard.log`(Agent 0건)와 이슈 목록 |
