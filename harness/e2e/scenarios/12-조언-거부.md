# 시나리오 12: 조언 거부

overview 9절 시나리오 12의 대본이다(T12, 이슈 #15). 통과 조건은 산출물로 적고, 산출물로 볼 수 없는 것은 "직접"(사용자가 직접 보고 확인한다)으로 표시한다.

## 사용자 입력 원문

- memo 목록에 정렬 옵션을 추가해 줘. [거부]

## 대역 설정

`setup --advisor-stub`. 지시 끝의 `[거부]`로 대역이 거부될 제안문을 낸다.

## 수치 경계

- 코디네이터 세션 실행: 최대 1번
- 하달(run-operator): 최대 0번
- 조언 판정: 같은 조언 id로 최대 2번(첫 제출 + 수정 1회, 소유자 결정 8-2)
- 재작업: 이슈당 2회까지, 3번째에 막힘(이슈 #2 결정 2-1)

## 통과 조건

`node harness/e2e/verify.mjs --scenario 12 --run <실행 폴더> --since <시작 시각>`이 "자동" 줄을 검사한다. `--dry`는 검사 항목만 나열한다. 산출물 칸의 첫 `` `...` ``가 검사식이다(쉼표로 여럿).

| 검사 | 확인 | 산출물 |
|---|---|---|
| 같은 조언 id로 거부가 2번(첫 제출 + 수정 1회) 기록됐다 | 자동 | `advice:거부 = 2` |
| 허용이 없다 | 자동 | `advice:허용 = 0` |
| 이슈가 없다 | 자동 | `issues = 0` |
| 기록된 해시와 거부 이유로 제안 / 이유 / 예상 결과를 물었다 | 직접 | 세션 출력 |
