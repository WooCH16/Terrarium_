# 시나리오 11: 조사

overview 9절 시나리오 11의 대본이다(T12, 이슈 #15). 통과 조건은 산출물로 적고, 산출물로 볼 수 없는 것은 "직접"(사용자가 직접 보고 확인한다)으로 표시한다.

## 사용자 입력 원문

- (가, 가벼운 확인) memo의 저장 파일(memos.json)을 다른 메모 도구가 읽을 수 있는지 조사해서 알려 줘. 코드는 바꾸지 마.
- (나, 깊은 조사, 새 세션) memo 코드 전체(모든 파일과 시험)를 읽고, 저장 방식을 SQLite로 바꿀 때 바뀌어야 하는 곳을 빠짐없이 조사해 목록으로 정리해 줘. 코드는 바꾸지 마.

## 대역 설정

기본.

## 수치 경계

- 코디네이터 세션 실행: 최대 1번
- 하달(run-operator): 최대 0번
- 조언 판정: 같은 조언 id로 최대 2번(첫 제출 + 수정 1회, 소유자 결정 8-2)
- 재작업: 이슈당 2회까지, 3번째에 막힘(이슈 #2 결정 2-1)

## 통과 조건

`node harness/e2e/verify.mjs --scenario 11 --run <실행 폴더> --since <시작 시각>`이 "자동" 줄을 검사한다. `--dry`는 검사 항목만 나열한다. 산출물 칸의 첫 `` `...` ``가 검사식이다(쉼표로 여럿).

| 검사 | 확인 | 산출물 |
|---|---|---|
| (가) 코디네이터가 직접 읽어 답했다(파일 몇 개, 이슈 없음) | 직접 | 세션 출력과 `guard.log` |
| (나) 조사 유형 이슈가 올라왔다 | 자동 | `body:유형: 조사` |
| (나) 조사 스크립트를 불렀다 | 자동 | `guard:run-research >= 1` |
| 작업 하달은 없었다 | 자동 | `guard:run-operator = 0` |
| 답을 사용자에게 보고했다 | 직접 | 세션 출력 |
