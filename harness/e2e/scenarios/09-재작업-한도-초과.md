# 시나리오 9: 재작업 한도 초과

overview 9절 시나리오 9의 대본이다(T12, 이슈 #15). 통과 조건은 산출물로 적고, 산출물로 볼 수 없는 것은 "직접"(사용자가 직접 보고 확인한다)으로 표시한다.

## 사용자 입력 원문

- memo 목록에 정렬 옵션을 추가해 줘.

## 대역 설정

워커를 결과가 늘 기준을 못 채우는 가짜 러너로 둔다: `HARNESS_PI_BIN`을 `harness/e2e/fakes/bad-worker.mjs`로. 리뷰어는 진짜 Jev.

## 수치 경계

- 코디네이터 세션 실행: 최대 1번
- 하달(run-operator): 최대 6번
- 조언 판정: 같은 조언 id로 최대 2번(첫 제출 + 수정 1회, 소유자 결정 8-2)
- 재작업: 이슈당 2회까지, 3번째에 막힘(이슈 #2 결정 2-1)

## 통과 조건

`node harness/e2e/verify.mjs --scenario 9 --run <실행 폴더> --since <시작 시각>`이 "자동" 줄을 검사한다. `--dry`는 검사 항목만 나열한다. 산출물 칸의 첫 `` `...` ``가 검사식이다(쉼표로 여럿).

| 검사 | 확인 | 산출물 |
|---|---|---|
| 막힌 이슈에 거부목록 라벨이 붙었다 | 자동 | `label:거부목록 >= 1` |
| 이슈당 하달이 첫 하달 + 재작업 2회를 넘지 않았다 | 자동 | `guard:run-operator <= 6` |
| 막힌 이슈로 모아 보고했다 | 직접 | 세션 출력 |
