# 시나리오 8: 요구 변경

overview 9절 시나리오 8의 대본이다(T12, 이슈 #15). 통과 조건은 산출물로 적고, 산출물로 볼 수 없는 것은 "직접"(사용자가 직접 보고 확인한다)으로 표시한다.

## 사용자 입력 원문

- (1턴) 시나리오 04와 같은 지시.
- (2턴, 이슈가 올라간 뒤) 생각해 보니 --sort created는 빼고 제목순만 있으면 돼. 대신 --reverse로 거꾸로도 보고 싶어.

## 대역 설정

기본. 2턴은 `--resume`.

## 수치 경계

- 코디네이터 세션 실행: 최대 2번
- 하달(run-operator): 최대 3번
- 조언 판정: 같은 조언 id로 최대 2번(첫 제출 + 수정 1회, 소유자 결정 8-2)
- 재작업: 이슈당 2회까지, 3번째에 막힘(이슈 #2 결정 2-1)

## 통과 조건

`node harness/e2e/verify.mjs --scenario 8 --run <실행 폴더> --since <시작 시각>`이 "자동" 줄을 검사한다. `--dry`는 검사 항목만 나열한다. 산출물 칸의 첫 `` `...` ``가 검사식이다(쉼표로 여럿).

| 검사 | 확인 | 산출물 |
|---|---|---|
| 영향받는 이슈에 보류 또는 취소 라벨이 붙었다(overview 3.6 "보류하거나 중단", 4.3 취소) | 자동 | `label:보류,취소 >= 1` |
| 새 이슈가 올라왔다 | 자동 | `issues >= 3` |
| 영향 없는 이슈는 그대로 진행했다 | 직접 | 이슈 목록과 세션 출력 |
