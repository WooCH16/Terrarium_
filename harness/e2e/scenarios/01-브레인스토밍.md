# 시나리오 1: 브레인스토밍

overview 9절 시나리오 1의 대본이다(T12, 이슈 #15). 통과 조건은 산출물로 적고, 산출물로 볼 수 없는 것은 "직접"(사용자가 직접 보고 확인한다)으로 표시한다.

## 사용자 입력 원문

- 메모 앱에 어떤 기능이 더 있으면 좋을지 같이 생각해 보자. 아직 만들지는 말고 아이디어만.

## 대역 설정

기본(`setup`, 진짜 어드바이저). 대상은 메모 예제.

## 수치 경계

- 코디네이터 세션 실행: 최대 1번
- 하달(run-operator): 최대 0번
- 조언 판정: 같은 조언 id로 최대 2번(첫 제출 + 수정 1회, 소유자 결정 8-2)
- 재작업: 이슈당 2회까지, 3번째에 막힘(이슈 #2 결정 2-1)

## 통과 조건

`node harness/e2e/verify.mjs --scenario 1 --run <실행 폴더> --since <시작 시각>`이 "자동" 줄을 검사한다. `--dry`는 검사 항목만 나열한다. 산출물 칸의 첫 `` `...` ``가 검사식이다(쉼표로 여럿).

| 검사 | 확인 | 산출물 |
|---|---|---|
| 이슈를 만들지 않았다 | 자동 | `issues = 0` |
| 어드바이저를 부르지 않았다 | 자동 | `guard:Agent = 0` |
| 오퍼레이터를 띄우지 않았다 | 자동 | `guard:run-operator = 0` |
| 조언 판정이 없다 | 자동 | `advice:all = 0` |
| 코디네이터가 직접 아이디어를 말했고 승인 절차를 꺼내지 않았다 | 직접 | 세션 출력 |
