# 시나리오 3: 정리본 경로

overview 9절 시나리오 3의 대본이다(T12, 이슈 #15). 통과 조건은 산출물로 적고, 산출물로 볼 수 없는 것은 "직접"(사용자가 직접 보고 확인한다)으로 표시한다.

## 사용자 입력 원문

- (1턴) 메모를 태그로 묶어 보는 기능을 생각 중이야. 같이 정리해 보자.
- (2턴, 코디네이터가 "보고서로 만들까요?"라고 물은 뒤) 응, 만들어 줘.
- (3턴, 정리본을 보여 준 뒤) 좋아, 그대로 진행해.

## 대역 설정

기본. 턴마다 `claude -p --resume`으로 이어 간다.

## 수치 경계

- 코디네이터 세션 실행: 최대 3번
- 하달(run-operator): 최대 1번
- 조언 판정: 같은 조언 id로 최대 2번(첫 제출 + 수정 1회, 소유자 결정 8-2)
- 재작업: 이슈당 2회까지, 3번째에 막힘(이슈 #2 결정 2-1)

## 통과 조건

`node harness/e2e/verify.mjs --scenario 3 --run <실행 폴더> --since <시작 시각>`이 "자동" 줄을 검사한다. `--dry`는 검사 항목만 나열한다. 산출물 칸의 첫 `` `...` ``가 검사식이다(쉼표로 여럿).

| 검사 | 확인 | 산출물 |
|---|---|---|
| 1턴 뒤 이슈가 없다 | 직접 | 1턴 뒤 이슈 목록 |
| 코디네이터가 "보고서로 만들까요?"로 시작했다 | 직접 | 세션 출력 |
| 승인 뒤 이슈가 올라왔다 | 자동 | `issues >= 1` |
| 근거 칸에 허용된 조언 해시가 있다 | 자동 | `body:허용된 조언: [0-9a-f]{64}` |
| 정리본 승인 전에는 조언 판정이 없다 | 직접 | `advice-log.jsonl` 시각과 세션 출력 비교 |
