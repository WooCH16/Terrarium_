# 계획: 지정 저장소를 설치할 때 알아서 만들기

**상태: 승인(2026-11-26).** 소유자: "설치할 때 알아서 만들게 하고, 두번째 프로젝트에서도 이름을 알아서만들어줘", "좋아 승인할게 계획에 넣어줘 자잘한건 알아서 채우고 계획을 크게 바꿀 문제들만 보고해". 바뀐 부분만 CI 작업(`plan-ci-merge-queue.md`) 뒤에 한다.

## 바라는 모습

```
node harness/setup.mjs --run <실행 폴더> --project <대상 폴더>
→ 지정 저장소를 비공개로 만들었다: <계정>/harness-issues-<대상 폴더 이름>
```

저장소를 직접 만들거나 이름을 줄 일이 없다. 두 번째 프로젝트도 같다.

## 정한 것

| 항목 | 정한 값 |
|---|---|
| 이름 | `<로그인 계정>/harness-issues-<대상 폴더 이름>`. `--project`가 없으면 예시 프로젝트 이름(`memo`). GitHub 이름 길이를 넘으면 자른다 |
| 만들기 | `--repo`가 없으면 묻지 않고 비공개로 만들고 이름을 출력한다. `--create-repo`는 남기되 없어도 된다 |
| 이미 있을 때 | 알아서 만든 저장소는 설명에 대상 폴더 경로의 해시(경로 자체는 아님)를 적어 둔다. 같은 폴더를 다시 설치하면 그 저장소를 다시 쓰고 알린다. 폴더 이름만 같고 다른 폴더면 `-2`, `-3`을 붙여 새로 만든다(기록이 섞이지 않게). 공개 저장소면 바꾸지 않고 멈춘다 |
| `--repo`를 줄 때 | 지금과 같다(없으면 `--create-repo`가 있어야 만든다. 이름을 잘못 쳐서 저장소가 생기지 않게) |
| `--refresh` | `--repo`가 없으면 실행 폴더 `harness.json`의 값을 읽는다. 저장소를 바꾸지 않는다 |
| `--no-clone` | 지금처럼 `--repo`가 필요하다 |
| 이미 설치한 실행 폴더 | 그대로 둔다. 옮기거나 이름을 바꾸지 않는다 |
| 로그인 | `gh auth login`은 처음 한 번 필요하다. 로그인 계정을 읽지 못하면 지금처럼 멈춘다 |

## 앱 (아직 하지 않음: 확인 대기)

- 설치 화면의 지정 저장소 칸은 비워 둘 수 있게 한다. 비우면 위 규칙의 이름을 쓰고, 만들기 확인 창 없이 설치한다.
- 설정에 저장해 둔 지정 저장소는 새 설치에 자동으로 채우지 않는다. 칸에 직접 적을 때만 그 저장소를 쓴다.
- 화면 모양은 바꾸지 않고 안내 문구와 필수 여부만 바꾼다.

## 문서

README의 "비공개 지정 저장소" 안내를 "설치하면 알아서 만듭니다"로 줄이고, 직접 정하는 방법은 `--repo` 한 줄로 남긴다.

## 할 일

1. `setup.mjs`: 이름 짓기, 묻지 않고 만들기, `--refresh`에서 저장된 값 읽기. 가짜 `gh` 시험 먼저.
2. 앱: `lib/install.mjs`, 설치 입력 검사, 안내 문구. 앱 논리 시험.
3. `preflight`와 README, `docs/operator.md`의 안내 문구.
4. 결정 기록과 변경 기록. beta 대상 PR로 올린다.

## 넣지 않은 것

여러 프로젝트가 저장소 하나를 같이 쓰기, GitHub 없이 쓰기.
