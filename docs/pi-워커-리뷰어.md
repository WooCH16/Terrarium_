# Pi 사용 결정 (워커·리뷰어)

> 이 문서는 근거 기록이다. 결정은 [ADR 0004](adr/0004-pi-worker-reviewer.md)(채택됨, 2026-11-18)를 따른다. 아래 "아직 정하지 않은 것"의 "Pi냐 Gemini냐"는 ADR 0004가 "Pi 하네스 + 모델(Claude, Gemini, Muse)"로 정리했다. "열린 항목 2.9"(`open-issues.md`)는 이 저장소에 없다.

이 문서는 저장소 문서에서 확인되지 않은 내용을 프로젝트 소유자의 결정으로 보충한 것입니다. 저장소 `docs/`와 `docs/adr/`에는 "Pi"라는 말이 없었습니다(2026-11-18 검색 기준).

## 소유자가 밝힌 내용

- **워커와 리뷰어는 Pi를 사용한다.**
- Pi는 터미널 코딩 에이전트 하네스이며, 앞서 Pi 오버레이는 주로 워커용으로 계획되었습니다.
- 리뷰어 역할은 읽기 전용 게이트입니다. 허용/거부 판정만 내고, 판정 형식은 `## 리뷰어 판정: 허용` 아래 `허용된 커밋: <40자리 해시>` 한 줄입니다.

## 소유자 설명 (2026-11-18)

- 리뷰어는 **Pi라는 하네스로 돌리고, 그 안의 모델은 Gemini**를 넣는다는 뜻이라고 설명함.
- **결정 (소유자, 2026-11-18): Pi가 `agy`를 거쳐 Gemini를 호출한다.** 외부 모델 위임 규칙(Gemini는 `agy`로 실행, 모델 이름과 실행 흔적을 보고서에 기록)과 맞는 방식임.
- 미검증: Pi에서 `agy`를 호출하는 방법, `agy`의 읽기 전용(`--sandbox`) 범위, 리뷰어 판정 형식 준수 여부.

## 충돌하는 기록 (확인 필요)

- 이전 기록: 리뷰어는 Pi로 만든다 → 이후 기록: 리뷰어는 연결된 Gemini로 쓸 것 같지만 미정이고, 실행 스크립트 구현이 끝난 뒤에 정한다.
- 즉 리뷰어를 Pi로 할지, Gemini(`agy`)로 할지는 **미정**이라는 기록이 가장 나중이었습니다. 이후 "워커와 리뷰어는 Pi"라는 설명이 이 결정을 바꾼 것인지는 확인되지 않았습니다. (ADR 0004가 이를 Pi 하네스 + 모델 선택으로 정리했습니다.)
- ADR 0003 부분 확인 기록: `agy --print`와 `--sandbox`가 있으나 제한 범위는 불명입니다. `gemini` 명령은 없고 Gemini는 `agy`로 씁니다.

## 리뷰어로 쓰려면 확인할 것 (두 모델 공통)

- 읽기 전용 강제가 실제로 되는지 (Pi와 `agy --sandbox` 모두 미검증).
- 리뷰어 모델이 워커 모델과 달라야 함.
- 판정 형식이 고정되어 있어야 함.

## 계획 (안)

확정된 구조: **리뷰어 = Pi 하네스 → `agy` → Gemini 모델.** 워커도 Pi로 돌린다.

| 순서 | 할 일 | 통과 기준 |
|---|---|---|
| 1 | Pi 설치 여부와 실행 방법 확인 (읽기 전용 도움말만) | Pi 실행 명령과 버전을 기록 |
| 2 | Pi가 `agy`를 호출하는 방법 확인 | `agy` 호출이 한 번 성공하고, 모델 이름과 실행 흔적을 얻음 |
| 3 | `agy --sandbox`의 읽기 전용 범위 시험 | 쓰기 시도가 막히고, 읽기는 허용됨 (실제 파일로 시험) |
| 4 | 리뷰어 판정 형식 시험 | `## 리뷰어 판정: 허용` 아래 `허용된 커밋: <40자리 해시>` 한 줄이 나옴. 형식이 어긋나면 거부로 처리 |
| 5 | 워커와 모델 분리 확인 | 리뷰어 모델이 워커 모델과 다름 |
| 6 | 공유 gh 계정 문제(판정자 식별) 결정 | 열린 항목 2.9의 결정을 기록 |

- 1~5는 실행 스크립트 구현이 끝난 뒤에 한다(소유자가 정한 순서).
- 시험 결과가 통과하지 않으면 리뷰어 모델을 바꾸는 것을 다시 논의한다.

## 아직 정하지 않은 것

- 리뷰어를 Pi로 확정할지, Gemini로 할지.
- 리뷰어 판정자를 식별할 방법(공유 gh 계정 문제, 열린 항목 2.9).
- Pi 오버레이 설계 문서가 저장소에 없음. 필요하면 따로 작성해야 함.
