# ADR 0004. 워커와 리뷰어는 Pi 하네스로 실행하고, 리뷰어는 워커와 다른 타입의 모델(Claude, Gemini, Muse)을 돌아가며 쓴다

> **경로 안내 (T9, 이슈 #12):** 본문의 `open-issues.md`(2-9)는 이 저장소에 없다. 판정자 식별의 미결은 이슈 #2와 `docs/checks/T5-pi-env.md`에 있다. ADR 0003 본문도 이 저장소에 없다. 본문은 고치지 않았다.

- 상태: **채택됨** (2026-11-18, 소유자 승인). 아래 시험 1~6은 아직 실행하지 않았다.
- 날짜: 2026-11-18
- 대체: **ADR 0002 결정 B의 리뷰어 실행 방식**("리뷰어를 코디네이터의 하위 에이전트로 부른다")과 **ADR 0003 결정 A의 워커 실행 방식**("오퍼레이터가 `run-worker`로 부르고 모델은 `claude`, `codex`, `gemini`, `muse` 중 하나")을 **대체한다.** 0003의 해당 결정은 `01-overview.md`의 요약으로만 확인했고 0003 본문은 이 저장소에 없어 대조하지 못했다. 0003 본문과의 대조는 **아직 하지 않았다**(미확인).
- 범위: 워커와 리뷰어가 **무엇으로 실행되는가**만 정한다. 리뷰어의 두 기능(조언 허용/거부, 결과 보고서 허용/거부)과 허용/거부 판정의 의미, 어드바이저·오퍼레이터·코디네이터의 실행 방식은 바꾸지 않는다.

## 배경

저장소 문서 어디에도 Pi가 없었고, 소유자의 결정으로만 확인되었다(`pi-워커-리뷰어.md`). 리뷰어를 Pi로 할지 Gemini로 할지 미정이라는 이전 기록과 충돌하는 부분도 있었다. 2026-11-18에 소유자가 다음 세 가지로 정리했다.

1. Pi로 실행하고, **그 안에 적힌 모델**을 사용한다.
2. 리뷰어는 **Pi → `agy` → Gemini**, 읽기 전용, 판정 형식 고정이다.
3. 이 결정을 새 ADR로 남긴다.
4. 결정 A와 B를 사용자가 확인했다. 리뷰어가 쓸 수 있는 모델에 Claude를 더하고, 워커와 리뷰어가 쓰는 모델의 상세(Claude, Gemini, Muse)를 정했다.

ADR 규칙상 결정을 바꿀 때는 옛 ADR을 고치지 않고 새 ADR을 쓴다.

## 결정 A. 워커는 Pi 하네스로 실행하고, 모델은 이슈에 적힌 것을 쓴다

**결정**

- 워커는 Pi로 실행한다. 작업 하나에 워크트리 하나를 쓰고 끝나면 오퍼레이터에게 보고하는 규칙은 그대로다.
- Pi는 실행 하네스일 뿐이고 모델은 정하지 않는다. 쓸 모델은 이슈의 `워커 모델` 칸에 적힌 값을 따르고, 그 값이 가리키는 모델은 아래 "모델 상세"를 따른다.
- 허용하는 워커 모델 값은 `claude`, `gemini`, `muse`다. **`codex`는 허용 목록에서 뺀다**(사용자 결정, 2026-11-18). 이는 ADR 0003 결정 A의 기존 목록(`claude`, `codex`, `gemini`, `muse`)을 바꾸는 것이다.
- 오퍼레이터가 워커를 부르는 길은 시작 스크립트(`run-worker`)로 유지한다. 스크립트가 Pi를 띄운다.

**이유**

- 사용자가 워커와 리뷰어를 Pi로 돌리기로 했다.
- 모델 선택을 이슈 쪽에 두면 코디네이터와 오퍼레이터의 현재 이슈 양식(`워커 모델` 칸)을 바꾸지 않아도 된다.

**확인됨:** "안에 적힌 모델"을 "이슈의 `워커 모델` 칸에 적힌 모델"로 읽는 해석을 사용자가 맞다고 확인했다(2026-11-18).

## 결정 B. 리뷰어는 Pi로 돌리고, 모델은 Gemini(`agy` 경유), Claude, Muse 중에서 쓴다

**결정**

- 리뷰어는 코디네이터의 하위 에이전트가 아니라 **Pi 하네스로 실행되는 별도 실행**이다. Gemini는 Pi → `agy` → Gemini 모델로 부르고, **Claude와 Muse도 리뷰어 모델로 쓸 수 있다.** Pi가 Claude와 Muse를 부르는 방법은 시험 2에서 확인한다.
- **읽기 전용**이다. 파일을 쓰거나 고치지 않는다.
- **판정 형식은 고정**이다. `## 리뷰어 판정: 허용` 아래에 `허용된 커밋: <40자리 해시>` 한 줄이 나와야 한다. 이 형식이 아니면 **거부로 처리**한다.
- 리뷰어 결과에는 사용한 **모델 이름**을 남기고, Gemini이면 **`agy` 실행 흔적**도 남긴다. 없으면 Gemini 결과로 인정하지 않는다(프로젝트의 `agy` 위임 규칙과 같다).
- 리뷰어의 두 기능(조언 허용/거부, 결과 보고서 허용/거부)과 호출 시점은 ADR 0002 결정 A를 따른다.

**이유**

- 리뷰어는 허용/거부만 내는 게이트라서 쓰기 권한이 필요 없고, 읽기 전용이면 워커나 오퍼레이터가 한 일을 건드리지 못한다.
- 판정이 해시 한 줄에 묶여 있어야 기계가 판정을 읽을 수 있고, 형식이 어긋난 응답이 허용으로 오해되지 않는다.
- 이 문서의 이전 발언 충돌(Pi냐 Gemini냐)은 "Pi 안에서 Gemini를 쓴다"로 정리된다.

## 결정 C. 리뷰어 모델은 워커 모델과 달라야 한다

**결정**

- 리뷰어는 **워커와 다른 타입의 모델**로 돌린다. 타입은 모델 값(`claude`, `gemini`, `muse`)을 뜻한다. 같은 이슈에서 리뷰어 타입과 워커 타입이 같으면 안 된다.
- 리뷰어 후보는 **Claude, Gemini, Muse**다. 워커의 타입을 뺀 두 후보를 **번갈아(순환)** 쓴다.
  - 워커가 `claude`이면 `gemini`와 `muse`를, 워커가 `gemini`이면 `claude`와 `muse`를, 워커가 `muse`이면 `claude`와 `gemini`를 번갈아 쓴다.
- 고르는 일은 리뷰어를 띄우는 스크립트가 한다. 이슈에 리뷰어 칸을 따로 두지 않는다.
- 순환 단위와 순서는 **미결**이다. 시작값은 "판정 한 번(조언 판정 또는 보고서 판정)마다 다음 후보로" 넘기는 것이다 `[보충]`. 순환 위치를 어디에 기록할지도 미결이다.

**이유**

- 같은 모델이 만든 것을 같은 모델이 검토하면 같은 오류를 같이 놓칠 수 있다.
- 후보를 번갈아 쓰면 특정 모델의 편향이 한 방향으로 쌓이지 않는다.
- 후보가 셋이면 어떤 워커 타입이든 리뷰어 후보가 둘 남아 항상 번갈아 쓸 수 있다.

## 모델 상세

워커와 리뷰어가 쓰는 모델의 이름은 사용자가 정한 값을 그대로 적는다. 정확한 모델 ID는 해당 CLI로 확인해 기록한다.

| 모델 값 | 상세 | 비고 |
|---|---|---|
| `claude` | Claude Haiku 5.5 | 모델 ID `claude-haiku-5-5` |
| `gemini` | Gemini 4 Hydrogen | `agy models`의 ID는 `gemini-4-hydrogen-{low,medium,high,xhigh}`로 추론 강도별로 나뉜다. 쓸 강도는 미정이다 |
| `muse` | Muse Spark 1.3 Contributor | 제공 API의 모델 ID는 `muse-spark-1.3`, Contributor 등급은 `-contributor` 접미사로 알려져 있다(2차 자료). Pi에서 부르는 방법은 미확인이다. Contributor 등급은 요금이 낮은 대신 전송한 데이터를 제공자가 학습에 쓸 수 있으므로, 리뷰어에게 넘기는 코드와 문서가 공개 가능한지 확인하고 쓴다 |

- 소유자가 구두로 정한 이름(`하이드라진`, `1.3 Spark 기여자`)을 정식 이름으로 옮겼다. `gemini`는 `agy models` 목록에서 확인했고 `Hydrazine`이라는 모델은 없어서 `Hydrogen`으로 해석했다. `muse`는 웹 검색(2차 자료)으로 확인했다. 두 해석 모두 소유자의 확인이 필요하다.
- 기존 허용 목록에 있던 `codex`는 사용자 결정으로 뺐다(결정 A).
- 세 모델 모두 워커와 리뷰어 후보로 쓴다(결정 A, B, C).

## 시험 계획 (이 ADR이 의존하는 미검증 사항)

아래는 `pi-워커-리뷰어.md`의 계획을 옮긴 것이다. 1~5는 **실행 스크립트 구현이 끝난 뒤**에 한다. 시험이 통과하지 않으면 리뷰어 모델을 바꾸는 것을 다시 논의하고, 필요하면 이 ADR을 새 ADR로 대체한다.

| 순서 | 할 일 | 통과 기준 |
|---|---|---|
| 1 | Pi 설치 여부와 실행 방법 확인 | Pi 실행 명령과 버전을 기록 |
| 2 | Pi가 `agy`를 호출하는 방법과 Claude, Muse를 부르는 방법 확인 | 각각 호출이 한 번 성공하고 모델 이름과 실행 흔적을 얻음. `agy models`로 Gemini 모델 ID 확인 |
| 3 | `agy --sandbox`의 읽기 전용 범위 시험 | 쓰기 시도가 막히고 읽기는 허용됨(실제 파일로 시험) |
| 4 | 판정 형식 시험 | 고정 형식이 나오고, 어긋나면 거부로 처리됨 |
| 5 | 워커와 리뷰어 타입 분리와 순환 확인 | 리뷰어 타입이 워커 타입과 다르고, 워커 타입마다 나머지 두 모델이 번갈아 나옴 |
| 6 | 판정자 식별(공유 gh 계정) 결정 | `open-issues.md` 2-9의 결정을 기록 |

## 검토한 대안

- **리뷰어를 하위 에이전트로 유지(0002 결정 B):** 구현이 단순하지만 Gemini 호출과 읽기 전용 강제를 Claude Code 하위 에이전트 안에서 보장할 방법이 없고, 사용자가 Pi로 돌리기로 했다.
- **리뷰어를 `agy`만으로 직접 호출(Pi 없이):** 사용자가 Pi 하네스를 쓰기로 했으므로 채택하지 않았다.
