# ADR 0001. 하네스의 형태: 역할, 실행, 소통, 권한, 환경

> **일부 대체됨 →** 결정 1과 결정 2는 [ADR 0002](0002-reviewer-gates-advice.md)의 결정 A, B로 대체되었다. 이 두 결정은 0002를 읽는다. 결정 3, 4, 5와 미확인 사항 표는 유효하다.

> **일부 대체됨 →** [ADR 0003](0003-operator-harness.md)(채택됨). 조사 요청 경로(결정 3의 "조사 요청은 예외"), 오퍼레이터 내부 설계의 범위 제한, 미확인 사항 표의 조사 관련 두 줄이 대체되었다. 대체된 부분은 아래에 취소선과 표시로 남겼다.

- 상태: **채택됨** (결정 1, 2는 대체됨)
- 날짜: 2026-11-12
- 범위: 코디네이터 설계. 오퍼레이터, 워커, 리뷰어, 어드바이저의 내부 설계는 이 ADR의 범위 밖이며, 코디네이터와의 접점만 다룬다. (**오퍼레이터는 ADR 0003이 설계하므로 범위 제한이 넓어졌다.**)
- 세부 규칙(숫자, 양식, 질문 기준 등)은 `docs/overview.md`에 있다. 이 ADR은 바꾸기 어려운 구조 결정만 담는다.

## 배경

처음 요청은 3계층 에이전트 하네스(코디네이터 → 오퍼레이터 → 워커)였다. 설계 논의 중에 리뷰어와 어드바이저가 더해져 역할이 5개가 되었다. 이번에는 사용자와 유일하게 대화하는 **코디네이터**만 설계한다.

가장 피할 실패의 우선순위는 **요구 누락 > 요구 왜곡 > 과도한 호출**이며, 아래 결정은 이 순서를 지키는 방향으로 정했다.

## 결정 1. 역할은 5개이고, 코디네이터는 범용이다

> **대체됨 →** [ADR 0002 결정 A](0002-reviewer-gates-advice.md). 아래 내용은 유효하지 않다.

**결정**

- 역할은 코디네이터, 어드바이저, 오퍼레이터, 워커, 리뷰어 5개다.
- 코디네이터가 하는 일은 사용자와 대화, 정리본 작성과 승인, 작업 분해와 이슈 등록·하달, 완료 기준 대조, 사용자 보고, 자신의 기록과 선호 문서 관리다.
- 코디네이터는 범용 고성능 모델이고 특정 영역의 지식을 내장하지 않는다. 영역 지식은 사용자가 미리 준비한 영역별 어드바이저가 **제안문**으로 제공한다. 어드바이저는 조언만 하고, 분해와 이슈 등록과 하달의 최종 판단과 실행은 코디네이터가 한다.
- 조사는 두 갈래다. 코디네이터는 가벼운 확인을 직접 하고 깊은 조사는 오퍼레이터에게 시킨다. 어드바이저는 자료가 필요하면 직접 조사하지 않고 오퍼레이터에게 조사 작업을 시켜 결과를 받은 뒤 제안문을 쓴다. 조사 요청은 이슈 없이 오퍼레이터를 직접 호출해 묻고 결과를 바로 받는다.
- 오퍼레이터의 결과 보고서는 리뷰어의 허용을 거친 것만 코디네이터가 완료 기준과 대조한다.

**이유**

- 코디네이터의 일(정리본, 분해, 분배, 대조, 보고)은 분야와 무관한 절차라서 범용이 맞고, 영역 전문 판단까지 맡기면 요구 왜곡 위험이 커진다.
- 대조를 코디네이터에 두면 승인된 요구를 가장 정확히 아는 쪽이 최종 확인을 하고, 리뷰어는 산출물이 맞는지, 코디네이터는 승인된 요구를 다 채웠는지로 서로 다른 것을 본다.

**검토한 대안**

- 어드바이저가 분해와 이슈 등록까지 맡는 안: 중간 전달은 줄지만 영역 사이의 의존을 이어 줄 주체가 비고, 요구에 대한 책임이 코디네이터에게서 흐려져 기각했다.

## 결정 2. 코디네이터만 상시 실행하고 나머지는 필요할 때 호출한다

> **대체됨 →** [ADR 0002 결정 B](0002-reviewer-gates-advice.md). 아래 내용은 유효하지 않다.

**결정**

- 코디네이터는 사용자와 대화하는 동안 계속 켜져 있다.
- 어드바이저는 영역 구분이 필요할 때 불러서 제안문을 받고 끝낸다.
- 오퍼레이터와 워커는 이슈를 하달하면 시작하고 일이 끝나면 종료한다. 오퍼레이터는 코디네이터나 어드바이저가 조사를 시킬 때도 시작한다.
- 리뷰어는 결과 보고서가 올라올 때 불러서 허용/거부를 받고 끝낸다.

**이유**

- 모든 역할의 상시 실행은 비용과 컨텍스트 부담이 크다.
- 상태를 이슈에 남기므로(결정 3), 코디네이터 세션이 끊겨도 복구할 수 있다.

**검토한 대안**

- 코디네이터 세션 안에서 모든 역할을 하위 에이전트로 호출하는 안: 모든 결과가 코디네이터 세션으로 돌아와 컨텍스트를 빠르게 채워 기각했다.

## 결정 3. 역할 사이의 연락은 GitHub 이슈로 한다

**결정**

- 하달, 결과 보고서, 허용/거부 의견은 GitHub Issues로 주고받는다. ~~단, **조사 요청은 예외**로 이슈 없이 세션에서 오퍼레이터를 직접 호출한다(결정 1).~~ **(대체됨 → ADR 0003 결정 D: 조사도 이슈로 하달한다.)**
- 이슈와 문서를 둘 저장소는 **사용자가 지정**하며, **비공개 저장소**여야 한다. 코디네이터가 스스로 정하지 않는다.
- 공개 저장소로 지정되어 있으면 쓰지 않고 사용자에게 알린다.

**이유**

- 이슈가 작업표, 담당, 상태, 분배 기록을 이미 제공하므로 진행 화면과 알림을 새로 만들지 않아도 된다.
- 세션이 끊긴 뒤에도 이슈 목록으로 어느 작업이 분배되었는지 복구할 수 있다.
- 이슈에는 요구사항과 작업 내용이 적히므로 공개되면 외부에 노출된다.

**검토한 대안**

- 저장소 안의 폴더에 이슈 한 건당 문서 한 개를 두는 로컬 파일 방식: 진행 화면, 알림, 상태 관리를 직접 만들어야 해서 기각했다.

## 결정 4. 코디네이터의 쓰기 권한은 지정 저장소의 이슈와 문서뿐이다

**결정**

- 쓰기는 지정 저장소의 이슈와 문서(기록 문서, 보존 노트, 선호 문서, 어드바이저 목록)에만 한다.
- 읽기는 지정 저장소, 실행 환경의 사용량 통계, 다른 역할이 올린 결과 보고서와 제안문, 그리고 작업 대상 프로젝트의 파일과 문서(읽기 전용의 가벼운 확인에 한함)다.
- 깊은 조사는 직접 하지 않고 오퍼레이터에게 시킨다. 이미 있는 사실을 확인하는 일은 가벼운 확인, 해석이 필요한 일은 깊은 조사이며, 가벼운 확인에는 한도(파일 3개 또는 읽기 3번, 시작값)를 두고 넘기면 중단해 위임한다. 애매하면 깊은 조사로 본다.
- 작업 대상 프로젝트에는 쓰지 않는다. 수정과 실행은 하지 않는다. 비밀값은 어떤 문서에도 적지 않는다.
- 권한을 넓히려면 이 ADR을 고치지 않고 새 ADR을 쓴다.

**이유**

- 확인 가능한 사실까지 사용자나 다른 역할에게 물으면 호출이 늘고 느려지므로 가벼운 확인은 직접 한다. 컨텍스트 소모와 비밀값 노출 위험을 줄이려고 깊은 조사는 오퍼레이터에게 맡기고, 쓰기와 실행은 하지 않는다.
- 이슈가 한 저장소에 모여야 진행 화면과 "어디까지 진행했어?"라는 질문에 한 곳에서 답할 수 있다.

**검토한 대안**

- 코디네이터가 대상 프로젝트를 전혀 읽지 않고 모든 조사를 다른 역할에 넘기는 안: 사소한 확인까지 다른 역할을 불러야 해서 호출이 늘고 느려져 기각했다.

## 결정 5. Claude Code 세션 기반으로 하되, 환경에 의존하는 부분은 접점으로 분리한다

**결정**

- 코디네이터는 Claude Code 세션 기반으로 설계한다. 규칙은 지시 문서로, GitHub 연동은 `gh`로 처리한다.
- 컴팩션 신호, 사용량 통계, GitHub처럼 실행 환경에 의존하는 부분은 코디네이터의 규칙과 분리된 접점으로 두어, 환경을 바꾸거나 기능을 더할 때 규칙을 다시 쓰지 않게 한다.
- 나중에 발전시킬 것으로 정한 것은 여러 사용자·팀 협업, 영역을 코디네이터가 제안하는 확장, 어드바이저 호출 상한, 픽셀형 진행 화면이며 이번 범위 밖이다.

**이유**

- 지금까지의 결정이 이미 Claude Code를 전제한다(컴팩션은 하네스가 하고, 규칙은 파일로 두고 다시 읽으며, 이슈는 `gh`로 처리).
- 코드 없이 설계하는 이번 범위에서 별도 프로그램을 만들지 않고 시작하되, 이후 확장 여지를 남긴다.

**검토한 대안**

- Claude Agent SDK 기반의 독립 프로그램: 컨텍스트, 사용량, 컴팩션 시점을 직접 제어할 수 있으나 별도 프로그램 구현 부담이 이번 범위와 맞지 않아 기각했다.

- 이후 ADR은 `0002`, `0003`처럼 번호를 올려 쓰고, 결정을 바꿀 때는 새 ADR로 대체한다. 방법은 `docs/adr/README.md`를 따른다.
- 이 ADR의 결정이 대체되면 이 문서 맨 위와 해당 결정 바로 아래에 "대체됨 → 새 ADR 번호와 결정" 경고를 달고, 색인을 같은 작업에서 함께 고친다.
