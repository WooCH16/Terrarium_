# ADR 0013. 관제탑은 소유자의 새 화면(`app/tower`), 하달된 만큼만 세션이 뜨고 끝나면 사라짐, 앱은 스스로 업데이트

- 상태: **채택됨**
- 날짜: 2026-11-24
- 관련: 소유자 결정 8-36(8-18·8-29 고침), 8-37. ADR 0011 결정 1·2·6과 덧붙임의 나머지, ADR 0012 결정 4를 대체한다. ADR 0010 결정 8에 보탠다
- 작업 기록: `docs/checks/app-screen-replace.md`, 화면이 읽는 것: `docs/app-screen.md`

## 배경

- ADR 0011은 저장소 루트의 예전 관제탑 파일(`index.html`, `js/`, `css/`)을 본창으로 쓰고 ORCHESTRA 칸에만 코디네이터 터미널을 넣었다. ADR 0012는 그 화면의 카드 다섯을 역할 오퍼레이터(dev·design·tester·plan·sec)로 늘 채웠다.
- 소유자는 새 Terrarium 화면을 만들어 예전 관제탑을 바꾸라고 했다(2026-11-24). 새 화면은 코디네이터 창 하나를 가운데 두고, 코디네이터가 실제로 부른 세션만 둘레에 창으로 그린다. 그래서 "카드 다섯은 늘 그 팀, 빈 자리 없음"(8-29)은 맞지 않게 됐다.
- 설치판을 고칠 때마다 사용자가 설치 파일을 다시 받아 실행해야 했다. 소유자는 다시 설치하지 않고 "업데이트할 버전이 있다"는 알림을 원했다.

## 결정

1. **본창은 `app/tower/`의 새 화면이다.** React UMD 템플릿(`index.html`, `app.js`, `runtime.js`, `terminal.js`)이고 의존은 `app/package.json`의 `react`·`react-dom` 18.3.1이다. 저장소 루트의 예전 관제탑 파일(카드 다섯, 팀 상세, 통합, 사무실, 브라우저 목 데이터)은 지웠다. 진행 기록은 설정 화면에 그대로 있다.
2. **코디네이터는 가운데 코디네이터 창의 대화형 Claude Code 터미널이다.** xterm과 `node-pty`로 잇는 방식, 명령줄, 세션 id, 세션 표지 변수 지우기, 설정 화면, 의존 관리는 ADR 0011 결정 3·4·5·7 그대로다.
3. **세션은 실행 폴더의 기록을 읽어서만 그린다.** 메인 프로세스의 `FlowTracker`(`app/lib/flow.mjs`)가 `guard.log`, `advice-log.jsonl`, `handoffs/`를 1초마다 읽어 이벤트로 바꾼다. 앱은 CLI를 띄우지 않고 하네스 흐름도 바꾸지 않는다.
   - 어드바이저는 코디네이터의 `Agent` 호출마다 하나, 오퍼레이터는 하달 하나에 하나(이름은 그 팀: `개발 Operator` 등), 워커는 그 하달에서 워커를 부른 이슈마다 하나다. 하달하지 않은 팀과 하달에 없는 이슈는 뜨지 않는다. 미리 자리를 잡지 않는다.
   - 일이 끝난 세션(조언이 통과한 어드바이저, 끝난 워커, 하달이 끝나고 워커가 다 사라진 오퍼레이터)은 ✓를 5초 보인 뒤 사라진다. 다시 부르면 새로 뜬다. 오류로 끝난 세션은 남는다.
   - 새 지시가 와도 화면을 처음부터 다시 그리지 않고 남은 창에 새 세션만 더한다.
   - JEV 표시는 실제 Jev 판정 동안만 켠다(어드바이저 쪽은 조언 판정, 오퍼레이터 쪽은 리뷰어 판정과 워커 모델 고르기).
   - 워커 모델은 보기만 한다. 모델은 하네스(Jev 라우팅)가 정한다.
4. **확대·이동은 화면 스스로 한다.** 배경 끌기, 휠, 세션이 뜨면 맞춤이다. 창 배율(`setZoomFactor`)은 쓰지 않는다(ADR 0011 결정 6 대체). 터미널은 배율을 되돌려 1배로 그린다.
5. **위쪽 칸.**
   - 사용량은 앱이 `--settings`로 더한 statusline 명령이 남긴 파일(`coordinator-status.json`)을 3초마다 읽는다. 값이 없으면 지어내지 않고 "첫 답 뒤 표시"를 보인다.
   - 사용량 단추를 누르면 계정별 한도 창이 열린다(`app/lib/limits.mjs`). Claude(5시간·주간·컨텍스트)와 GitHub(`gh api rate_limit`)는 막대로 보인다. Pi(anthropic·meta)는 `pi auth check --no-refresh`의 연결 상태, Gemini·Jev는 키 보관 여부만 보이고 "제공사가 남은 한도를 알려 주지 않는다"고 적는다.
   - 프로필 단추는 없다. 계정 관리와 진행 기록은 톱니 → [설정 열기]에서 연다.
   - 왼쪽 위·오른쪽 위 칸은 각 모서리에 붙고, 끌거나 창 크기·해상도가 바뀌어도 화면 안에 남는다.
6. **창.** 흰 제목 표시줄은 숨기고 창 단추만 배경색 위에 둔다(위쪽 32px는 창 끌기 자리). 처음 크기는 1440×900이되 화면 작업 영역보다 크지 않다. 세션이 도는 중에 창을 닫으면 "진행중인 세션이 있습니다." 경고와 [확인]·[돌아가기]를 띄운다.
7. **화면 시험 `/testgo`.** 코디네이터 터미널에 `/testgo`를 치면 3분 동안 가짜 세션 이벤트로 화면을 시험하고 원래 화면으로 돌아간다. 그 줄은 코디네이터에 보내지 않고, 모델·GitHub를 부르지 않으며, 실행 폴더에 쓰지 않는다.
8. **설치판은 스스로 업데이트한다(ADR 0010 결정 8에 보탬).**
   - `electron-updater` 6.8.11이 GitHub 릴리스(`WooCH16/Terrarium_`)의 `latest.yml`을 앱을 켜고 10초 뒤와 6시간마다 본다. 설치판(`app.isPackaged`)에서만 켠다.
   - 새 버전은 뒤에서 받고, 다 받으면 [지금 재시작](조용히 깔고 다시 켬)과 [나중에](앱을 닫을 때 깔림)를 보인다. 세션이 도는 중이면 재시작 전에 6번의 경고를 띄운다.
   - 릴리스에는 설치 파일, `.blockmap`, `latest.yml`을 대시 이름(`Terrarium-Setup-<버전>.exe`)으로 함께 올린다. `npm run dist`는 올리지 않는다(`--publish never`). 올리는 것은 사람이 한다.
   - 실행 폴더의 `harness.json`은 앱 설치 폴더의 하네스(`resources/harness`)를 가리키므로 훅·실행 스크립트는 앱과 함께 바뀐다. 실행 폴더에 복사된 규칙·에이전트·설정(`CLAUDE.md`, `.claude/`)은 바뀌지 않아 `setup --refresh`로 다시 쓴다.

## 결과

- 예전 관제탑의 카드·팀 상세·통합·사무실과 그 매핑(`app/lib/tower.mjs`)은 지웠다. ADR 0012의 담당 팀, 하달 하나 = 한 팀, 하달·워커 기록, `--base`(결정 1·2·3·5)는 그대로이고, 새 화면은 그 기록을 읽는다.
- 남는 한계는 `docs/known-limitations.md`에 적었다: 업데이트는 GitHub 릴리스와 네트워크가 있어야 함, 서명 없음, Pi·Gemini·Jev의 남은 한도는 볼 수 없음, 실행 폴더에 복사된 규칙·설정은 `setup --refresh`로 따로 다시 써야 함.
