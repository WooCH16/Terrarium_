## 배경

첫 버전(ADR 0002)은 오퍼레이터와 워커를 코디네이터의 하위 에이전트로 부르려 했다. 하위 에이전트는 코디네이터 세션 안에서 돌아 권한 경계(훅)를 역할마다 따로 둘 수 없고, 워커가 대상 프로젝트를 고치는 동안 코디네이터 세션이 막힌다. 합치기, CI, 보고, 정리를 맡을 주체도 없었다.

## 결정

**A. 오퍼레이터는 독립 세션이다.** 코디네이터가 시작 스크립트(`run-operator`)로 Claude 세션을 띄운다. 하달 하나가 세션 하나이고, 하달 번호 `h<N>`이 브랜치·워크트리·로그·정리의 단위다. 오퍼레이터는 이슈에 적힌 `워커 모델`로 워커를 부른다(`run-worker`). 이슈 본문에 `워커 모델`과 `유형`(작업·조사) 칸을 더한다. 오퍼레이터와 코디네이터는 Claude로 고정한다.
- 대체됨: 워커 실행 방식과 모델 목록은 ADR 0004 결정 A, ADR 0009. 워커 모델·유형을 고르는 일은 ADR 0008(Jev 라우팅).

**B. 오퍼레이터는 합치기·보고 담당이다.** 작업 코드를 직접 고치지 않는다(워커의 일). 워커 결과를 통합 브랜치에 합치고, 결과 보고서를 이슈 댓글(`## 결과 보고서`)로 올리고, 상태 라벨을 갱신한다. 보고서에 커밋 해시, 지정·실제 모델, 시도 횟수, 사후 검사 자료를 더한다. 편집 도구는 통합 브랜치 폴더에서 충돌 해결에만 쓰고, 그 커밋은 작성자로 표시해 CI를 한 번 더 돌린다.

**C. 합치기는 머지 큐 방식의 CI를 거친다.** 이슈 결과를 하나씩 통합 브랜치에 합치며 매번 시험을 돌린다. 개인 계정 저장소에서는 GitHub 머지 큐를 쓸 수 없어 지금은 같은 순서를 로컬에서 흉내 낸다(`ci.mergeQueue: "local"`). `main`은 사용자가 반영을 결정한 뒤 반영 모드(`run-reflect`)에서만 바뀌고, 허용 판정과 묶인 커밋만 들어간다.

**D. 조사도 이슈로 하달한다.** 조사 요청은 `유형: 조사` 이슈를 올리고 `run-research`로 별도 오퍼레이터 세션을 띄운다. 진행 중인 하달을 기다리지 않는다. 결과는 오퍼레이터가 이슈 댓글로 올리고 기준 커밋 해시를 붙인다. ADR 0001·0002의 "이슈 없이 직접 호출"을 대체한다.

**E. 가장 먼저 풀 문제는 안전과 격리다.** 역할마다 훅 프로필을 두고(코디네이터, 오퍼레이터 작업·조사·반영 모드, 워커), 스크립트의 정해진 모양만 실행하게 한다. 중단 스크립트(`stop-operator`)가 하달의 모든 세션을 프로세스 단위로 끝내고 이름 공간을 정리한다. 스크립트 출력은 이슈마다 `#번호 | 상태 | URL` 한 줄과 정해진 종료 코드다. 병렬, 예산, 영역 확장은 이 위에 얹는 것이라 이번 범위 밖이다.
