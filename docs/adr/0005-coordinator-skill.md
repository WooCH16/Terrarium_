# ADR 0005. 코디네이터는 Skill 도구를 쓸 수 있다

- 상태: **채택됨**
- 날짜: 2026-11-18
- 범위: 코디네이터 세션의 도구 허용 목록. [ADR 0001 결정 4](0001-harness-shape.md)의 권한 경계에 Skill 도구 하나를 보탠다. 결정 4의 나머지 내용은 그대로 유효하다.

## 배경

ADR 0001 결정 4는 "권한을 넓히려면 이 ADR을 고치지 않고 새 ADR을 쓴다"고 정했다. 지금까지 코디네이터 세션은 훅(`harness/guard.mjs` → `harness/policy.mjs`)의 허용 목록 `COORDINATOR_TOOLS`에 Skill이 없어서 스킬을 부르지 못했다. 하네스 절차를 스킬로 묶어 쓰려면 코디네이터가 Skill 도구를 쓸 수 있어야 한다.

## 결정

- 코디네이터 세션의 허용 도구에 `Skill`을 넣는다. `harness/policy.mjs`의 `COORDINATOR_TOOLS`와 실행 명령의 `--allowedTools`(`harness/setup.mjs`, `harness/README.md`)에 함께 넣는다.
- Skill은 다른 권한을 열지 않는다. 스킬이 시키는 명령, 파일 쓰기, 하위 에이전트 호출은 결정 4와 훅의 허용 목록을 그대로 따르고, 목록 밖이면 훅이 막는다.
- 스킬 절차 중 막힌 단계가 있으면 코디네이터는 우회하지 않고 막힌 사실과 사유를 사용자에게 알린다(`harness/coordinator.md`).

## 이유

- 스킬은 절차를 담은 문서를 불러오는 일이라 그 자체로는 쓰기나 실행이 아니다. 실제 위험한 동작은 스킬이 시키는 도구 호출에서 생기고, 그 호출은 이미 훅이 하나씩 검사한다.
- 반복하는 하네스 절차를 스킬로 만들면 코디네이터가 같은 절차를 매번 다시 풀어 쓰지 않아도 된다.

## 검토한 대안

- 스킬별로 허용 목록을 따로 두는 안: 스킬이 늘 때마다 정책을 고쳐야 하고, 도구 호출 단위 검사로 이미 막을 수 있어 기각했다.

## 확인

- `harness/test/policy.test.mjs`: 코디네이터의 Skill 허용, Skill을 쓴 뒤에도 목록 밖 명령(`npm install`)과 도구(WebFetch)가 막히는지 시험한다.
