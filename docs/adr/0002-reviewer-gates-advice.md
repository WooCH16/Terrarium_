# ADR 0002. 리뷰어가 어드바이저 조언도 허용/거부하고, 첫 버전은 하위 역할을 하위 에이전트로 부른다

> **일부 대체됨 →** [ADR 0004](0004-pi-worker-reviewer.md)(채택됨, 2026-11-18). 결정 B의 "리뷰어를 하위 에이전트로 부른다"는 Pi 하네스 실행(Gemini는 Pi → `agy`, 또는 Claude, Muse)으로 대체되었다. 리뷰어의 두 기능(결정 A)과 어드바이저를 하위 에이전트로 부르는 부분은 유효하다.

> **경로 안내 (T9, 이슈 #12):** 본문의 `docs/overview.md`는 지금 `docs/01-overview.md`다. ADR 0003 본문(`0003-operator-harness.md`)은 이 저장소에 없다. 본문은 고치지 않았다.

> **일부 대체됨 →** [ADR 0003](0003-operator-harness.md)(채택됨). 결정 B의 "오퍼레이터는 코디네이터의 하위 에이전트", "워커는 오퍼레이터의 하위 에이전트", "오퍼레이터가 돌려주는 것은 댓글 위치와 한 줄 요약", 그리고 결정 A의 조사 요청 경로가 대체되었다. 어드바이저와 리뷰어를 하위 에이전트로 부르는 부분과 리뷰어의 두 기능은 유효하다. 대체된 부분은 아래에 취소선과 표시로 남겼다.

> **일부 대체됨 →** [ADR 0006](0006-advice-verdict.md)(채택됨, 2026-11-18). 결정 A의 조언 거부 처리 경로와 결정 B의 조언 판정 전달 방식이 대체되었다. 리뷰어의 두 기능은 유효하다.

- 상태: **채택됨**
- 날짜: 2026-11-13
- 대체: **ADR 0001의 결정 1과 결정 2를 대체한다.** 두 결정의 나머지 내용은 아래에 다시 적었으므로 이 ADR만 읽으면 된다. 0001의 결정 3, 4, 5와 "미확인 사항" 표는 그대로 유효하다(표의 한 줄은 아래 결정 B에서 확인됨으로 바뀐다).
- 범위: 0001과 같다. 코디네이터와 다른 역할 사이의 접점만 다룬다.

## 배경

하네스 첫 버전을 만들기 전에 사용자가 흐름을 다음처럼 정했다.

> 지시 → 코디네이터가 어드바이저에게 조언 요청 → 어드바이저 조언 → 리뷰어 허용 → 코디네이터가 이슈 등록 → 영역별 분배 → 오퍼레이터 → 작업 수만큼 워크트리 워커 → 워크트리마다 워커가 오퍼레이터에게 보고 → 오퍼레이터가 합치고 결과 보고 → 리뷰어 허용 → 코디네이터 대조 → 사용자 보고

0001에서는 리뷰어가 결과 보고서만 보았다. 사용자는 리뷰어의 기능을 **1. 결과 보고서 검토, 2. 허용/거부 결정** 두 가지로 정리했고, 허용/거부 결정은 어드바이저 조언에도 쓴다. 또 첫 버전은 대역 역할을 하위 에이전트로 만들기로 했는데, 0001 결정 2는 "모든 역할을 하위 에이전트로 부르는 안"을 기각했으므로 이 충돌도 여기서 정리한다.

## 결정 A. 역할은 5개이고, 리뷰어는 조언과 결과 보고서 두 곳에서 허용/거부한다 (0001 결정 1 대체)

**결정**

- 역할은 코디네이터, 어드바이저, 오퍼레이터, 워커, 리뷰어 5개다.
- 코디네이터가 하는 일은 사용자와 대화, 정리본 작성과 승인, 작업 분해와 이슈 등록·하달, 완료 기준 대조, 사용자 보고, 자신의 기록과 선호 문서 관리다.
- 코디네이터는 범용 고성능 모델이고 특정 영역의 지식을 내장하지 않는다. 영역 지식은 사용자가 미리 준비한 영역별 어드바이저가 **제안문(조언)**으로 제공한다. 어드바이저는 조언만 하고, 분해와 이슈 등록과 하달의 최종 판단과 실행은 코디네이터가 한다.
- 조사는 두 갈래다. 코디네이터는 가벼운 확인을 직접 하고 깊은 조사는 오퍼레이터에게 시킨다. 어드바이저는 자료가 필요하면 직접 조사하지 않고 오퍼레이터에게 조사 작업을 시켜 결과를 받은 뒤 제안문을 쓴다. ~~조사 요청은 이슈 없이 오퍼레이터를 직접 호출해 묻고 결과를 바로 받는다.~~ **(대체됨 → ADR 0003 결정 D: 조사도 이슈로 하달하고 최우선으로 처리한다.)**
- **리뷰어의 기능은 두 가지다.**
  1. **결과 보고서 검토:** 오퍼레이터의 결과 보고서를 검토하고 허용/거부한다. 허용된 보고서만 코디네이터가 완료 기준과 대조한다.
  2. **허용/거부 결정:** 어드바이저 조언이 나오면 허용/거부한다. 허용된 조언만 코디네이터가 이슈로 만든다.
- 조언이 거부되면 코디네이터가 **거부 이유와 함께 어드바이저에게 되돌려 수정하게 한다.** 반복 한도와 그 뒤의 처리는 overview 3.5절을 따른다.

> **대체됨 →** [ADR 0006](0006-advice-verdict.md) 결정 2, 4, 5. 어드바이저가 리뷰어를 직접 부르고, 거부 이유는 스크립트가 어드바이저에게 돌려주며, 2회 거부 뒤에는 스크립트가 코디네이터에게 알린다.

**이유**

- 코디네이터의 일은 분야와 무관한 절차라서 범용이 맞고, 영역 전문 판단까지 맡기면 요구 왜곡 위험이 커진다.
- 조언은 이슈와 완료 기준의 출발점이다. 조언이 틀리면 그 뒤의 이슈가 모두 틀어지므로, 영역 판단을 하지 않는 코디네이터 대신 리뷰어가 조언 단계에서 한 번 거른다.
- 대조를 코디네이터에 두면 승인된 요구를 가장 정확히 아는 쪽이 최종 확인을 하고, 리뷰어는 산출물과 조언이 맞는지, 코디네이터는 승인된 요구를 다 채웠는지로 서로 다른 것을 본다.

**검토한 대안**

- 리뷰어는 결과 보고서만 보고 조언은 코디네이터가 그대로 받는 안(0001): 호출이 한 번 줄지만, 영역 판단을 못 하는 코디네이터가 틀린 조언을 걸러낼 수 없어 요구 왜곡이 이슈까지 번지므로 기각했다.

## 결정 B. 코디네이터만 상시 실행하고, 첫 버전의 나머지 역할은 하위 에이전트로 부른다 (0001 결정 2 대체)

> **일부 대체됨 →** [ADR 0004 결정 B](0004-pi-worker-reviewer.md)(채택됨, 2026-11-18). 이 결정의 "리뷰어를 코디네이터 세션의 하위 에이전트로 부른다"는 Pi 하네스로 실행되는 별도 실행으로 대체되었다. 어드바이저를 하위 에이전트로 부르는 부분은 유효하다.

**결정**

- 코디네이터는 사용자와 대화하는 동안 계속 켜져 있다.
- 어드바이저는 영역 구분이 필요할 때 불러서 제안문을 받고 끝낸다.
- 오퍼레이터와 워커는 이슈를 하달하면 시작하고 일이 끝나면 종료한다. 오퍼레이터는 코디네이터나 어드바이저가 조사를 시킬 때도 시작한다.
- 리뷰어는 **어드바이저 조언이 나올 때와 결과 보고서가 올라올 때** 불러서 허용/거부를 받고 끝낸다.
- **첫 버전은 어드바이저, ~~오퍼레이터,~~ 리뷰어를 코디네이터 세션의 하위 에이전트로 부르고, ~~워커는 오퍼레이터의 하위 에이전트로 부른다.~~** **(오퍼레이터와 워커 부분은 대체됨 → ADR 0003 결정 A: 오퍼레이터는 코디네이터가 시작 스크립트로 띄우는 독립 세션이고, 워커는 오퍼레이터가 시작 스크립트로 부른다.)** 다만 컨텍스트가 차지 않도록 다음을 지킨다.
  - 결과 보고서와 리뷰어의 판정은 GitHub 이슈 댓글로 남긴다(0001 결정 3). 하위 에이전트가 코디네이터에게 돌려주는 것은 **댓글 위치와 한 줄 요약**뿐이다. **(오퍼레이터가 돌려주는 것은 대체됨 → ADR 0003 결정 A: 이슈마다 번호, 상태, URL만.)**
  - 이슈가 생기기 전에 오가는 조언과 조언에 대한 판정은 하위 에이전트가 바로 돌려준다. 코디네이터는 허용된 조언의 요지를 이슈의 근거 칸에 옮긴다. **(조언 판정 부분은 대체됨 → ADR 0006: 리뷰어 전용 폴더와 `run-reviewer --advice`로 하고, 허용된 제안문의 해시를 근거 칸에 적는다.)**
  - 워커의 보고는 오퍼레이터에게만 가고 코디네이터에게 직접 오지 않는다.

**이유**

- 모든 역할의 상시 실행은 비용과 컨텍스트 부담이 크다.
- 0001이 하위 에이전트 안을 기각한 이유는 "모든 결과가 코디네이터 세션으로 돌아와 컨텍스트를 채운다"였다. 결과의 본문을 이슈 댓글로 보내고 위치만 돌려받으면 그 이유가 사라진다.
- 하위 에이전트는 Claude Code 안에서 바로 쓸 수 있어, 첫 버전에서 별도 세션을 띄우고 연결하는 구현이 필요 없다.
- 상태를 이슈에 남기므로 코디네이터 세션이 끊겨도 복구할 수 있다.

**검토한 대안**

- 각 역할을 별도 Claude Code 세션으로 띄우는 안: 컨텍스트가 완전히 분리되지만 세션 사이의 시작·대기·결과 수신을 직접 만들어야 해서 첫 버전 범위와 맞지 않아 기각했다. 하위 에이전트의 컨텍스트 부담이 운영 중 문제로 드러나면 이 안으로 다시 검토한다.

## 0001 "미확인 사항" 표의 변경

| 항목 | 변경 |
|---|---|
| 다른 역할을 별도 세션으로 부를지 하위 에이전트로 부를지 | **확인됨:** 첫 버전은 하위 에이전트(결정 B). |
| 어드바이저가 제안문을 직접 반환하는가, 이슈 댓글로 남기는가 | **확인됨:** 이슈가 생기기 전이므로 직접 반환한다(결정 B). |
