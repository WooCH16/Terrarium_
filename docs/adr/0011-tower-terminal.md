# ADR 0011. 앱 화면은 소유자의 관제탑, 코디네이터는 ORCHESTRA 칸의 대화형 Claude Code 터미널

- 상태: **채택됨**
- 날짜: 2026-11-20
- 이슈: #39, #40
- 관련: 소유자 결정 8-18(8-14 고침), 9-5. ADR 0010 결정 2·4·7을 대체한다

## 배경

ADR 0010은 앱에 새 화면 넷(계정·설치·대화·진행)을 만들고, 코디네이터를 `claude -p` stream-json 자식 프로세스로 띄웠다. 두 가지가 맞지 않았다.

- **화면:** 소유자는 관제탑 화면(`index.html`, `css/`, `js/`, `assets/`)을 직접 만들었다. 결정 9-5는 그 화면을 앱 화면으로 쓰는 것이었다. 결정 8-14("새 화면")는 그 뜻과 달랐다.
- **세션:** `-p`에는 사람이 치는 입력창이 없어서 `/compact`, Esc로 끊기, `/login`을 쓸 수 없었다(시나리오 10, 알려진 한계 8의 "하달 중 대화").

## 결정

1. **본창은 소유자의 관제탑 화면이다.** 앱은 저장소 루트의 관제탑 파일을 그대로 읽는다. 사본을 두지 않는다. 설치본에서는 `resources/tower`로 복사된다. 같은 파일은 브라우저로 열면 지금처럼 목 데이터로 돈다.
2. **ORCHESTRA 칸만 바꾼다.** 앱에서 열면 `js/terminal.js`가 목 대화(`#messages`, `#chat-form`)를 숨긴다. 그 자리에 xterm 터미널을 띄우고, 실행 폴더에서 대화형 `claude`를 의사 터미널(`node-pty`)로 연결한다. 머리줄과 틀, 목록바, 오퍼레이터 카드, 팀 상세, 통합, 사무실은 손대지 않는다.
3. **코디네이터 명령은 `claude --setting-sources project,local --allowedTools "<README와 같은 목록>" --session-id <앱이 정한 uuid>`이다.** 다음에 열 때는 `--resume <그 id>`로 연다.
   - `--continue`는 쓰지 않는다. "이 폴더의 가장 최근 대화"가 시험용 `-p` 실행이나 오퍼레이터 세션일 수 있다.
   - 이어 열 대화가 없으면(첫 실행을 신뢰 확인에서 끝낸 경우 등) 새 id로 바로 다시 띄운다.
4. **세션 표지 변수는 넘기지 않는다.** 앱을 Claude Code 안에서 띄우면 `CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION` 같은 변수가 따라온다. 그대로 넘기면 코디네이터가 자식 세션으로 여겨 대화 기록을 남기지 않는다. 그 표지만 지우고, 사용자 설정 변수와 키는 그대로 둔다.
5. **관제탑에 없는 화면은 설정 창으로 옮긴다.** 계정, 실행 폴더 설치, 진행 기록이 여기에 해당한다. 메뉴 [설정]으로 연다. 터미널을 띄우는 조건은 그대로다. 목록에 있는 실행 폴더여야 하고, 사전 점검을 통과해야 한다.
6. **확대는 창의 배율로 한다.** 관제탑의 880×600 무대는 CSS `zoom`으로 창에 맞췄다. 그런데 xterm의 글자 칸 계산과 마우스 선택이 CSS `zoom`에서 어긋난다. 그래서 앱에서는 `webContents.setZoomFactor`로 맞춘다. 브라우저 목업은 지금처럼 CSS `zoom`을 쓴다.
7. **의존이 늘었다.** `node-pty` 1.1.0, `@xterm/xterm` 6.0.0, `@xterm/addon-fit` 0.11.0이다. 모두 `app/package.json`에만 둔다. `node-pty`는 N-API 미리 빌드된 파일을 쓰므로 컴파일러가 필요 없다(`npmRebuild: false`, `asarUnpack`).

## 확인 (2026-11-20, run-12 실행 폴더, 개발 실행)

| 통과 조건 | 결과 |
|---|---|
| Electron 45 메인 프로세스에서 `node-pty`로 `claude`를 띄운다 | `claude --version` 출력과 종료 코드 0 |
| ORCHESTRA 칸에 Claude Code 화면이 나온다 | 폴더 신뢰 확인 화면, 이어서 Claude Code 첫 화면(화면 캡처) |
| 친 말이 코디네이터에 가고 답이 온다 | "harness.json에 적힌 지정 저장소 이름만" → `Read` 뒤 맞는 저장소 이름(`<소유자>/<이름>`) 한 줄 |
| 훅이 돈다 | 그 `Read`가 `guard.log`에 허용으로 남음 |
| 대화 기록이 남고 이어 열린다 | 세션 표지를 지운 뒤 기록 파일이 생기고, 다시 띄우면 앞 대화가 보임 |
| 이어 열 대화가 없을 때 | `No conversation found` 뒤 새 id로 자동으로 다시 뜸(첫 시도에서 드러나 고침) |
| 설치 파일 | `resources/tower`(관제탑 파일)와 `app.asar.unpacked/node_modules/node-pty/prebuilds`가 들어감 |

미확인:
- 설치본에서 터미널이 뜨는지
- 하달 중 Esc를 눌렀을 때 어떻게 되는지(분리 실행된 하달은 일부러 남는다)
- `/compact`와 `PreCompact` 훅(시나리오 10)

## 결과와 위험

- **목 데이터:** 관제탑의 오퍼레이터 카드, 팀 상세, 통합, 사무실은 아직 목 데이터다. 진짜 코디네이터 옆에 가짜 팀과 진행률이 보인다. 팀 다섯 개라는 모양도 하네스의 하달·이슈 구조와 맞지 않는다. 어떻게 잇는지는 소유자가 정한다.
- **처음 띄울 때:** 대화형이라 폴더 신뢰 질문이 나온다. 여기서 "No"를 고르면 설정의 `permissions.allow`가 적용되지 않는다. 이때도 훅이 도는지는 대화형에서 확인하지 않았다(확인은 "Yes"로 했다).
- **창 크기:** 터미널 칸이 작다(창 크기에 따라 90×16 글자 안팎).
