# Terrarium 정의

Terrarium은 Claude Code 에이전트를 계층으로 나눠 일을 맡기는 개인용 하네스입니다. 사용자는 코디네이터 한 명과만 대화합니다.

## 역할

| 역할 | 하는 일 |
|---|---|
| 코디네이터 | 사용자와 대화하고, 요구를 정리해 승인받고, 작업을 이슈로 쪼개 하달하고, 결과를 대조해 보고합니다. |
| 어드바이저 | 영역 지식으로 작업 분해 제안문을 씁니다. 조언만 합니다. |
| 오퍼레이터 | 이슈를 받아 팀을 운영하고 보고서를 씁니다. 별도 세션입니다. |
| 워커 | 실제 작업을 합니다. Pi로 돌리며, 작업마다 워크트리 하나를 씁니다. 모델은 이슈의 `워커 모델` 칸에 적힌 값을 따릅니다. |
| 리뷰어 | 보고서를 허용/거부합니다. Pi로 돌리고, 모델은 워커와 다른 타입을 번갈아 씁니다. Gemini는 Pi가 `agy`를 거쳐 호출합니다. 읽기 전용이고 판정 형식이 고정되어 있습니다. |

## 모델

워커와 리뷰어가 쓰는 모델 값은 `claude`, `gemini`, `muse` 세 가지입니다. `codex`는 쓰지 않습니다.

| 모델 값 | 모델 |
|---|---|
| `claude` | Claude Haiku 5.5 |
| `gemini` | Gemini 4 Hydrogen |
| `muse` | Muse Spark 1.3 Contributor |

- 워커는 이슈에 적힌 모델 값을 씁니다.
- 리뷰어는 워커와 다른 타입의 모델로 돌립니다. 후보는 세 모델이고, 워커 타입을 뺀 나머지 둘을 번갈아 씁니다. 고르는 일은 리뷰어를 띄우는 스크립트가 합니다.
- 리뷰어의 판정 형식은 `## 리뷰어 판정: 허용` 아래에 `허용된 커밋: <40자리 해시>` 한 줄입니다. 이 형식이 아니면 거부로 처리합니다.

## 결과 흐름

오퍼레이터 보고서 → 리뷰어 허용/거부 → 코디네이터 완료 기준 대조 → 사용자 보고

## 계획 (리뷰어와 워커)

1. Pi 실행 방법 확인
2. Pi가 `agy`를 호출하는 방법과 Claude, Muse를 부르는 방법 확인
3. `agy --sandbox`의 읽기 전용 범위 시험
4. 판정 형식 시험
5. 워커와 리뷰어 타입 분리와 순환 확인
6. 판정자 식별(공유 gh 계정) 결정
