# 소유자 앱 확인 시나리오 (#36 계정 화면, #41 설치 파일·서명)

main 병합(PR #1) 전에 소유자가 직접 해 보는 확인이다. 각 단계의 **기대 결과**와 다르면 그 단계 번호와 화면(또는 오류 문구)을 알려 준다.
결과 칸에 통과·실패·못 함을 적는다. 키 값이나 토큰은 어디에도 적지 않는다.

- 시간: 시나리오 1~3 약 30분, 시나리오 4(깨끗한 계정 설치) 약 20분.
- 앱이 쓰는 폴더: `%APPDATA%\Terrarium`(설정 `prefs.json`, 암호화된 키 `keys.json`, 실행 폴더 `runs\`). 지금 계정에서 해 보면 여기에 기록이 남는다.
- 화면 구성: 본창은 관제탑이고 맨 아래 ORCHESTRA 칸이 코디네이터 터미널이다. 설정은 관제탑 왼쪽 목록 맨 아래 **[설정]** 단추를 누르면 본창 안에서 화면이 바뀐다(계정·설치·진행 탭). 실행 폴더 선택, API 키, 지정 저장소는 **[저장] → 저장하기**를 눌러야 적용되고 관제탑으로 돌아온다. **[돌아가기]**나 Esc는 저장하지 않는다.

## 시나리오 2: 로그인 창 열기 (#36)

각 단추가 별도 터미널 창으로 로그인 명령을 띄우는지 본다. 이미 로그인된 것은 창이 뜨는지만 보고 닫아도 된다.

| # | 할 일 | 기대 결과 | 결과 |
|---|---|---|---|
| 2-1 | **Claude Code** 단추 | 새 터미널 창에 `claude`가 뜬다. 로그인 안 된 계정이면 로그인 안내가 나온다 | |
| 2-2 | **GitHub (gh)** 단추 | 새 터미널 창에 `gh auth login` 질문이 뜬다. 끝까지 진행하면 로그인된다 | |
| 2-3 | **Pi — Anthropic** 단추 | `pi auth login anthropic`이 뜬다 | |
| 2-4 | **Pi — Meta (muse)** 단추 | `pi auth login meta`가 뜬다 | |
| 2-5 | 로그인을 마친 뒤 사전 점검을 다시 누른다 | 로그인한 항목이 통과로 바뀌고, 워커 모델 수가 늘어난다 | |

## 시나리오 3: API 키 보관과 전달 (#36, #37)

| # | 할 일 | 기대 결과 | 결과 |
|---|---|---|---|
| 3-1 | 계정 탭의 API 키 칸에 Jev(TypeSafe) 키를 넣고 저장한다 | "저장됨" 같은 상태로 바뀌고 **값은 화면에 다시 보이지 않는다** | |
| 3-2 | 탐색기에서 `%APPDATA%\Terrarium\keys.json`을 메모장으로 연다(내용을 어디에 붙여 넣지 않는다) | 키 원문이 아니라 알아볼 수 없는 문자열(암호화된 base64)만 있다 | |
| 3-3 | 사전 점검을 다시 누른다 | Jev 키 항목이 통과한다(앱이 보관한 키를 환경 변수로 넘겼다는 뜻). 워커 모델이 1곳 이상이면 전체 통과 | |
| 3-4 | 앱을 끄고 다시 띄운 뒤 사전 점검 | 키를 다시 넣지 않아도 Jev 키가 통과한다 | |
| 3-5 | (선택) Gemini 키도 넣고 점검 | gemini 워커 항목이 통과로 바뀐다 | |

## 시나리오 4: 실행 폴더 설치와 코디네이터 한 마디 (#36의 잠금 해제 확인)

| # | 할 일 | 기대 결과 | 결과 |
|---|---|---|---|
| 4-1 | 설정 > 실행 폴더 설치: 지정 저장소, 실행 폴더 이름(예: `app-check`), 대상 프로젝트는 **비워 둔다**(메모 예제) → 설치 | 설치가 끝나고 실행 폴더 목록에 `app-check`가 생긴다. 대상 프로젝트를 비웠으니 워크플로 질문 창은 뜨지 않는다 | |
| 4-2 | 관제탑으로 돌아와 실행 폴더를 고른다 | ORCHESTRA 칸에 코디네이터(claude) 터미널이 뜬다 | |
| 4-3 | 터미널에 "지금 상태를 한 줄로 알려 줘"를 친다 | 코디네이터가 답한다. 하달은 시키지 않는다(사용량을 쓰지 않게) | |
| 4-4 | 계정 탭에서 Jev 키 칸을 비우고 저장한 뒤 **사전 점검을 다시 누르고**, 앱을 다시 띄운다 | 점검이 실패하고 코디네이터 터미널이 다시 잠긴다(사전 점검 안내). 잠금은 마지막 점검 결과를 따르므로 점검을 다시 해야 바뀐다. 시스템 환경 변수에 같은 키가 있으면 통과할 수 있다 | |
| 4-5 | 키를 다시 넣고 점검 | 통과로 돌아온다 | |

## 시나리오 5: 깨끗한 사용자 계정에 설치 (#41)

새 Windows 사용자 계정에서 처음 받는 사람처럼 설치한다.

| # | 할 일 | 기대 결과 | 결과 |
|---|---|---|---|
| 5-1 | Windows 설정 > 계정 > 기타 사용자 > 계정 추가(로컬 계정)로 시험용 계정을 만든다 | 계정이 생긴다 | |
| 5-2 | 설치 파일(`app\dist\` 아래 `Terrarium Setup <버전>.exe`)을 공용 폴더(예: `C:\Users\Public\Downloads`)에 복사한다 | 시험 계정에서 보인다 | |
| 5-3 | 시험 계정으로 로그인해 설치 파일을 실행한다 | 서명이 없어 **SmartScreen 경고**("Windows의 PC 보호")가 뜬다. "추가 정보 > 실행"으로 넘어간다. 이 경고가 사용자에게 어떻게 보이는지가 서명 결정의 근거다 | |
| 5-4 | 설치를 마치고 시작 메뉴에서 Terrarium을 띄운다 | 관제탑 화면이 뜨고 시나리오 1-1과 같은 안내가 보인다 | |
| 5-5 | 계정 탭에서 사전 점검 | 이 계정에는 gh·claude 로그인이 없으니 해당 항목이 실패하고 고치는 방법이 보인다(앱이 죽지 않는다) | |
| 5-6 | 설정 > 앱 > 설치된 앱에서 Terrarium을 제거한다 | 깨끗이 지워진다 | |
| 5-7 | 끝나면 시험 계정을 지운다 | — | |
