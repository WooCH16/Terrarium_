# 거부(deny) 기록 정리 (2026-11-13 ~ 2026-11-24)

무엇이 왜 막혔는지 한곳에 모은 문서입니다. 출처는 세 가지입니다.

1. **하네스 훅**(`harness/guard.mjs` + `policy.mjs`): 실행 폴더 15개(run-5~19)의 `guard.log`(코디네이터·어드바이저)와 `logs/<하달>/guard.log`(오퍼레이터·워커).
2. **개발 세션**: 이 저장소를 만든 Claude Code 세션(2026-11-18~24)에서 거부된 도구 호출.
3. **`/goal` 목표 확인 훅**: 같은 개발 세션에서 턴 끝내기가 막힌 경우.

명령 원문의 개인 경로와 저장소 이름은 `<실행 폴더>`, `<지정 저장소>`로 바꿨습니다. 숫자는 그 기간의 기록을 그대로 센 것입니다.

## 4. `/goal` 목표 확인 훅 (개발 세션, 39번)

`/goal`을 걸면 턴을 끝낼 때마다 Claude Code가 목표 문장이 이뤄졌는지 판정하고, 아니면 끝내기를 막는다. 연달아 막히면 "Goal paused"로 멈춘다.

| 목표 | 막힘 | 결과 | 원인 |
|---|---|---|---|
| 오픈소스화 후 beta에 커밋·푸시 | 1 | 이어서 끝냄 | 일을 하기 전에 승인을 물으며 멈췄다 |
| CI가 덜 돌게 작업·PR 묶기 | 11 | Goal paused → 해제 | 목표 문장 안에 "계획을 만들면 승인 전에는 구현하지 않음"이 있었다. 승인 대기를 훅은 미완료로 봤다 |
| 새 UI로 앱 교체 … 하달부터 끝까지, exe까지 | 27 | Goal paused 두 번 → 해제 | 끝까지 가려면 이슈 반영(#53)과 비용이 드는 종단 실행에 사용자 승인이 있어야 했다. 나중의 결정("53은 그대로 둬")도 목표 문장을 바꾸지 않아 계속 미완료로 셌다 |

**피하는 법:** 끝나는 조건을 승인 지점까지로 쓴다(예: "계획을 보고하고 승인을 기다리면 끝"). 결정이 바뀌면 `/goal clear` 뒤 다시 건다. 승인이나 비용이 끼는 일은 `/goal` 대신 보통 지시로 맡긴다(결정 8-34).

## 5. 보이는 경향과 손볼 후보 (아직 바꾸지 않음)

권한 규칙을 넓히는 일은 보안 결정이라 소유자 승인 뒤에만 한다. 아래는 후보다.

- **명령 연결 금지(합계 67건)가 가장 큰 마찰이다.** 막는 것이 맞다. 대신 역할 문서에 "한 명령씩, `cd` 대신 절대 경로, `-C`"를 예와 함께 더 앞에 둘 수 있다.
- **읽기 전용 `gh issue view --json`·`--jq`(19건)과 `git log/rev-parse/diff/show` 모양(27건)**은 쓰기 위험이 없는 읽기다. 허용 모양을 넓히면 오퍼레이터가 덜 돈다.
- **`ToolSearch`(15건)**는 도구를 찾기만 한다. 허용해도 실제 도구 사용은 그대로 훅을 거친다.
- **어드바이저의 셸 읽기(23건)**는 규칙대로 막힌 것이다. 어드바이저 문서에 "대상 프로젝트는 Read·Glob·Grep으로만 읽는다"를 더 분명히 둘 수 있다.
- **`SubagentHandback`(7건)**은 어드바이저가 하위 에이전트로 돌 때 Claude Code가 자동으로 부르는 끝 보고 도구로 보인다. 결과는 일반 응답으로 전달되지만, 막히는 줄이 기록을 어지럽힌다.
