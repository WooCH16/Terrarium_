# 앱 화면 교체 작업 기록 (2026-11-24, 0.2.0-beta.1)

소유자가 만든 새 Terrarium UI로 앱의 관제탑 화면을 바꾸고, 실제 하네스 기록에 이어 붙인 작업의 기록입니다. 무엇을 바꿨는지는 [CHANGELOG](../../CHANGELOG.md)의 0.2.0-beta.1, 화면이 무엇을 읽는지는 [docs/app-screen.md](../app-screen.md)에 있습니다. 여기에는 진행 중에 생긴 문제와 해결, 판단한 것을 남깁니다.

## 판단한 것

| 갈림길 | 고른 것 | 까닭 |
|---|---|---|
| 새 UI의 메인 프로세스(CommonJS, 목 오케스트레이터)를 그대로 쓸까 | 쓰지 않음. 화면(`renderer/`)만 옮기고, 기존 앱의 메인 프로세스(코디네이터 터미널, 설정, 키, 사전 점검, 설치)에 이어 붙임 | 앱은 ES 모듈이라 그대로 넣으면 `require`에서 깨진다. 기존 메인 프로세스에 하네스와 이어진 기능이 다 있다 |
| 코디네이터 창의 한 줄 입력칸 | 진짜 Claude Code 터미널로 바꿈 | 코디네이터는 대화형이다(신뢰 질문, `/login`, Esc, 권한 질문). 한 줄 입력으로는 다 다룰 수 없다 |
| 세션을 어디서 알아내나 | 실행 폴더의 기록을 읽기만 함(`guard.log`, `advice-log.jsonl`, `handoffs/`). 앱이 CLI를 띄우지 않음 | 하네스가 이미 남기는 기록이라 하네스 흐름을 바꾸지 않는다. 실제로 생긴 하달·워커만 그려서 "필요 없는 오퍼레이터·워커는 안 뜸"이 저절로 지켜진다 |
| 어드바이저를 어떻게 알아보나 | 실제 실행 기록(run-18의 `guard.log`)의 행으로 규칙을 정함: 코디네이터의 `Agent` 줄 = 어드바이저 시작, `agent_type: advisor` 줄 = 그 일, 코디네이터가 다른 도구를 다시 쓰면 끝 | 훅을 더하지 않고 있는 기록만 쓴다. 호출 설명이 기록에 없어서 `guard.mjs`의 `summary`에 Agent의 `description`을 더했다 |
| 미리 자리 잡기(`run.plan`) | 쓰지 않음 | 뜨지 않을 세션의 자리를 잡으면 "필요한 만큼만"이 화면에서 깨진다 |
| `YOLO`, "bypass permissions on" | 지움 | 하네스의 권한 상태와 다른 거짓 장식이다. 이것을 맞추려고 권한을 건너뛰는 옵션을 켜지 않는다 |
| 워커 모델 바꾸기 단추 | 보기만 하는 표시로 바꿈. 하네스에 없는 `codex`는 고를 수 없음 | 모델은 하네스가 이슈마다 정한다(Jev 라우팅) |
| 사용량 | 코디네이터 statusline의 `rate_limits`(Claude Code 문서로 확인)를 앱이 `--settings`로 더한 statusline 명령이 파일로 남김. 값이 없으면 "사용량 모름" | 확인한 출처만 보이고, 없으면 숫자를 지어내지 않는다. 실행 폴더의 설정 파일은 건드리지 않는다 |
| 워크스페이스 탭 | 열어 둔 실행 폴더 탭으로 바꿈(누르면 그 폴더로 코디네이터를 옮김) | 아무 일도 하지 않는 탭을 두지 않는다 |
| 예전 관제탑 | 지움(폴더 패널, 팀 상세·통합·사무실, 다섯 자리 카드, 브라우저 미리보기 포함) | 교체 요청이다. 진행 기록은 설정 화면에 남아 있다 |
| 앱 버전 | 0.2.0-beta.1, beta 브랜치의 미리보기 | `main`은 사용자 승인 전이다 |

## 문제와 해결

| # | 문제 | 원인 | 해결 | 다시 시도 |
|---|---|---|---|---|
| 1 | 의존성 설치 명령이 작업 도구의 권한 판정에서 한 번 거부됨 | 확인하지 못함(읽기 명령과 묶어 보낸 첫 시도만 거부되었다) | 설치 명령만 따로 다시 보내 통과. 새 UI가 적어 둔 고정 버전(react·react-dom 18.3.1, @fontsource/jetbrains-mono 5.3.0) | 1회 |
| 2 | 스모크에서 코디네이터 터미널이 뜨지 않음("File not found") | 의사 터미널(node-pty)은 `node`라는 이름만으로는 실행 파일을 찾지 못한다. claude가 npm 셔틀일 때의 대체 경로도 같은 문제였다 | `where node`로 절대 경로를 찾아 씀 | 스모크 1회 |
| 3 | 개발팀 하달이 끝나자마자 실행이 "끝"으로 판정되어, 뒤이은 테스터팀 하달이 다음 실행으로 넘어감 | 잠잠함을 코디네이터의 마지막 도구 사용부터 셌다. 하달 동안 코디네이터는 `run-operator`를 기다리느라 도구를 쓰지 않는다 | 세션이 끝난 때부터도 잠잠함을 셈 | 스모크 1회 |
| 4 | 흐름 기록 검사가 앞쪽 줄을 못 봄 | 화면은 기록을 6줄만 기억한다 | 스모크는 메인 프로세스가 보낸 이벤트 전체로 순서를 검사 | 스모크 1회(3번째에 27개 모두 통과) |
| 5 | 축소한 화면에서 터미널 글자가 흐려지고 마우스 선택 위치가 어긋날 수 있음 | 화면 전체가 `transform: scale`로 줄어든다(xterm은 변환을 모른다) | 터미널 요소만 배율을 되돌려(크기 ×z, scale 1/z) 늘 1배로 그림. 스모크가 배율 1과 0.7에서 확인 | 설계 단계 |
| 7 | 실제 하달(run-18 h26)에서 오퍼레이터 창의 할 일이 "이슈 없음" | 하달 직후 `dispatch.json`의 `live`는 null(run-operator가 이슈를 거르는 중)이고, 창은 처음 뜰 때의 할 일을 쓴다. 가짜 코디네이터는 처음부터 `live`를 채워서 못 잡았다 | `live`가 없으면 `requested`를 보임. 흐름 시험에 "live: null로 시작" 경우를 더함. 0.2.0-beta.2로 다시 빌드 | 1회 |
| 6 | 스모크 결과 파일에 이 컴퓨터의 임시 경로와 GitHub 계정 이름이 들어감 | 검사 상세에 화면 글자를 그대로 남김 | `app/out/`을 `.gitignore`에 넣고 커밋에서 뺌 | 커밋 전 검사 |

## 확인한 것

- `cd app && npm test`: 16개 통과(흐름 시험 4개 포함).
- `cd app && npm run smoke`: 27개 통과. 하달 한 번에 어드바이저 1, 하달한 두 팀(개발·테스터)의 오퍼레이터 2, 개발팀 하달 이슈의 워커 2만 뜨고, 하달하지 않은 팀은 뜨지 않음. 워커 없이 끝난 하달은 오퍼레이터만. 하위 세션 없는 차례는 세션 0.
- `node scripts/test.mjs --fast`: 451개 중 450 통과, 1 건너뜀(플랫폼).
- `node scripts/check.js`: 통과.
- 설치 파일: 커밋된 파일만 있는 깨끗한 작업 트리에서 `electron-builder --win nsis`로 만들었다(작업 폴더의 무시된 파일·`.env`가 섞이지 않게). 풀린 설치본(`win-unpacked/resources`)에서 계정 이름, 이메일, 비공개 저장소 이름, 개인 폴더 경로를 찾아 하나도 없음을 확인했다. 하네스 폴더에 `.env`·로그가 없다.
- 설치본 실행: 임시 앱 데이터 폴더(`--user-data-dir`)로 띄워 DevTools 프로토콜로 확인했다(화면을 찍지 않음). asar 안의 React·글꼴·xterm이 읽히고, 첫 화면("실행 폴더 없음", OFFLINE)이 그려지고, Claude Code 버전을 실제로 읽었다. 사용자의 실제 앱 데이터는 쓰지 않았다.
- 진짜 Claude Code(2.1.330)로 코디네이터 띄우기: `claude --help`에 `--settings`가 있다. 앱(소스)을 임시 앱 데이터로 띄워 이미 쓰던 실행 폴더를 열었더니, 앱이 넘긴 인자(`--setting-sources`, `--allowedTools`, `--settings`, `--session-id`)에 옵션 오류 없이 폴더 신뢰 질문까지 떴다(메시지는 보내지 않음). statusline 파일은 신뢰 질문을 넘겨야 생기는데, 사용자의 신뢰 설정을 바꾸지 않으려고 답하지 않았다. 그래서 **사용량 칸은 실제 코디네이터로는 아직 미확인**이다(statusline 스크립트 자체는 표본 JSON으로 파일을 쓰는 것을 확인).
- 실제 기록 재생: 실제 실행 폴더 넷(run-8, 12, 18, 19)의 기록을 읽기만 해서 흐름 모듈에 처음부터 넣었다. 예외 없이 돌았고, 뜰 세션 수가 기록과 같았다(어드바이저 = 허용된 Agent 줄 수, 오퍼레이터 = 하달 수, 워커 = start 줄 수). 팀 없는 옛 하달은 팀 이름 없이 "Operator · h<N>"으로 뜬다.
- **실제 하달(종단 확인):** 앱(소스, 임시 앱 데이터)에서 진짜 Claude Code 코디네이터로 로컬 흐름 실행 폴더(메모 예제)를 열고 "메모에 `--version` 옵션을 이슈 1개로 만들어 개발팀에 하달, 리뷰어 판정까지만, 반영 전에 멈춤"을 지시했다(약 6분, 모델 비용 발생, 지정 저장소에 이슈 하나가 생김). 화면 결과:
  - 어드바이저 7개(패널 초안 3, 교환 3, 최종 1): 코디네이터의 Agent 호출 수와 같다. 모두 DONE.
  - 오퍼레이터: 개발팀 h26 하나만. 다른 네 팀은 뜨지 않음.
  - 워커: 이슈 #53 하나(하네스가 고른 gemini, 2회 시도 끝 완료), h26 아래에 붙음.
  - 흐름 기록: 하달 → 워커 호출 → 워커 완료 → h26 끝 → Jev 리뷰어 판정 · 이슈 #53 → 모든 하위 세션 완료, 코디네이터 DONE. 코디네이터는 반영 전에 멈췄다(반영은 하지 않음).
  - 사용량: statusline 파일에 실제 값이 들어와 위쪽 칸에 5시간 한도와 재설정 시각이 보였다. 위 "사용량 칸 미확인"은 이것으로 확인됐다.
  - 이 실행에서 결함 하나(문제 7번)를 찾아 고쳤다.
- **설치본으로 진짜 코디네이터:** 0.2.0-beta.2 커밋으로 풀어 만든 설치본(`win-unpacked`)을 임시 앱 데이터로 띄워 같은 실행 폴더를 열었다. 진짜 코디네이터가 떠 `running`이 되었고, statusline 명령이 설치본 경로(`app.asar.unpacked/lib/statusline.mjs`)에서 돌아 상태 파일을 썼다. 설치본으로 하달까지 돌리지는 않았다(아래).
- **남긴 결정(사용자 몫):** 실제 하달로 생긴 이슈 #53(h26, 리뷰어 판정까지 끝남)은 반영하지 않았다. 반영 승인은 사용자만 할 수 있어서, 작업 도구가 대신 승인하는 지시를 막았고 그게 맞다. 설치본으로 새 하달을 돌리면 열린 이슈가 하나 더 생기므로 그것도 하지 않았다. 설치본과 소스의 화면·흐름 코드는 같고, 설치본에서 달라지는 경로(asar 안의 화면·의존성, asar 밖의 statusline, 하네스 위치)는 위에서 각각 확인했다. **사용자 결정(2026-11-24): #53은 반영도 닫기도 하지 않고 그대로 둔다.** 그래서 하달부터 머지까지 한 번에 도는 종단 확인은 이번 작업에서 하지 않았다(머지 승인이 사용자 몫이고, 새 하달은 이슈를 하나 더 만든다).
- **앱 교체 마무리:** 이 세션에서 소스로 띄워 두었던 예전 화면의 앱을 닫고(그 실행 폴더에 도는 하달 없음을 먼저 확인), 같은 실제 앱 데이터로 새 화면의 앱을 다시 띄웠다. 흐름 시험과 스모크의 기록은 하네스의 기록 함수로 쓴 것이고, 어드바이저 규칙은 실제 실행 기록의 모양에서 정했다.

## 0.2.0-beta.3: Jev 불빛, 오퍼레이터 이름, 끝난 세션 사라짐, `/testgo`

사용자 요청: Jev 판정 때 Jev 표시가 켜지는지 확인, 새 지시가 와도 세션을 처음부터 다시 그리지 말고 유지하며 고칠 것(작업 중에 추가), 오퍼레이터에 팀 이름(개발·디자인 등), 워커는 그대로, `/testgo` 화면 시험(어드바이저 3, 오퍼레이터 전부, 워커는 한 명씩 늘어남, Jev는 일정 간격으로 켜짐, 3분 뒤 돌아감), 일이 끝난 어드바이저·워커·오퍼레이터는 사라지고 다시 부르면 다시 뜸.

### 확인해 보니

- **Jev 표시는 Jev 판정과 이어져 있지 않았다.** 예전 코드는 어드바이저나 오퍼레이터 창이 DONE이 될 때 1.4초 켜기만 했다. 실제 판정(`run-reviewer --advice`, 조언 판정 기록, 코디네이터의 `run-reviewer --issue`) 때는 켜지지 않았다. 흐름 모듈이 판정을 읽어 `jev.active` 이벤트를 보내도록 고쳤고, DONE 때 켜던 것은 지웠다.
