# 코디네이터 설계

- 실행 문서: [`harness/coordinator/AGENT.md`](../harness/coordinator/AGENT.md) (설치하면 실행 폴더의 `CLAUDE.md`)
- 스킬: `harness/coordinator/skills/coordinator-*` 10개(직접 지시, 정리본, 조언, 이슈, 하달, 판정·대조, 반영, 조사, 기록, 예외). 설치하면 실행 폴더의 `.claude/skills/`에 들어가고 Skill 도구로 부른다(ADR 0005). 다른 역할의 스킬은 훅이 막는다.
- 전체 흐름과 양식: [01-overview.md](01-overview.md). 이 문서는 코디네이터 한 역할만 모아 적은 것이고, 자세한 절차는 overview와 실행 문서를 따른다.
- 결정: ADR 0001, 0002, 0005, 0006, 0008, 0010, 0011

## 1. 개요

코디네이터는 사용자와 대화하는 유일한 역할이다. 실행 폴더에서 도는 **대화형 Claude Code 세션**이고 상시 떠 있다. 사용자의 지시를 이슈로 바꿔 오퍼레이터에게 하달하고, 리뷰어를 통과한 결과를 완료 기준과 대조해 사용자에게 보고한다.

특정 영역의 지식을 내장하지 않는다. 영역 지식은 어드바이저의 제안문으로 받는다(ADR 0002).

## 2. 하는 일과 하지 않는 일

| 하는 일 | 하지 않는 일 |
|---|---|
| 사용자와 대화, 정리본 작성과 승인 받기 | 대상 프로젝트 고치기, 실행하기, 시험 돌리기 |
| 어드바이저를 불러 제안문 받기(조언 id를 정해 넘김) | 제안문 직접 쓰기, 조언 판정 띄우기(어드바이저가 한다) |
| 라우팅(`route-issue`)으로 워커 모델·유형·난이도를 받아 이슈 등록 | 워커 모델을 스스로 고르기 |
| 오퍼레이터 하달(`run-operator`, `run-research`, `run-reflect`), 중단, 이어 기다리기 | 워커를 직접 부르기 |
| 결과 보고서 판정 띄우기(`run-reviewer --issue`), 허용된 보고서를 완료 기준과 대조 | 허용·거부 판정 |
| 기록 문서, 보존 노트, 선호 문서 관리. 가벼운 확인(파일 3개·읽기 3번까지) | 깊은 조사(오퍼레이터에게 조사 이슈로) |

## 3. 실행

- **명령:** `claude --setting-sources project,local --allowedTools "Bash Write Edit Read Glob Grep Agent TodoWrite Skill"`. 앱은 여기에 `--session-id`(처음)나 `--resume`(다음부터)을 붙인다(ADR 0011).
- **설치:** `setup.mjs`가 실행 문서의 `{{REPO}}`, `{{ISSUES}}`, `{{MEMO}}`, `{{HARNESS}}`, `{{PROJECT}}`, `{{RUN}}`을 채워 실행 폴더의 `CLAUDE.md`로 쓴다. 어드바이저 정의, 훅 설정(`.claude/settings.json`), `harness.json`도 함께 만든다.
- **어디서:** 터미널에서 직접 띄우거나(Claude CLI 버전), 데스크톱 앱의 관제탑 ORCHESTRA 칸에서 띄운다(앱 버전). 둘은 같은 세션이다.

## 4. 입력과 출력

- **입력:** 사용자의 말. 스크립트 출력 한 줄(하달 결과, 판정 줄, 라우팅 세 줄). 이슈와 댓글. 어드바이저가 돌려준 판정 줄과 허용된 제안문(`handoffs/advice-<해시>.md`).
- **출력:** 지정 저장소의 이슈와 댓글, 지정 저장소 클론의 문서(기록, 보존 노트, 선호, 어드바이저 목록), 사용자 보고.

## 5. 흐름 (요약)

1. 대화가 기본이다. "~해줘"처럼 작업을 지시하면 직접 지시 경로, 큰 작업은 정리본을 써서 승인을 받는다.
2. 어드바이저를 부른다. 어드바이저가 제안문을 쓰고 리뷰어(Jev)의 허용을 받아 돌려준다. 같은 조언 id가 2번 거부되면 사용자에게 묻는다.
3. 허용된 제안문의 작업 단위마다 이슈 초안을 쓰고 `route-issue`로 워커 모델·유형·난이도를 받아 이슈를 만든다. 단위의 `담당 팀`(dev·design·tester·plan·sec)을 이슈의 `- 담당 팀:` 줄에 옮긴다. 없거나 다섯 값이 아니면 이슈를 올리지 않고 어드바이저에게 되돌린다(결정 8-29).
4. `run-operator`로 하달한다. 하달 하나는 한 팀의 이슈만 받고, 팀별로 의존 순서대로 한 팀씩 하달한다. 반영 전인 다른 하달 h<N>에 기대는 이슈는 `--base h<N>`을 붙여 그 위에서 시작한다(결정 8-31). 오퍼레이터가 워커를 부르고 결과 보고서를 이슈에 올린다.
5. `run-reviewer --issue`로 보고서를 판정받는다. 허용된 보고서만 완료 기준과 대조해 사용자에게 보고한다.
6. 허용된 이슈 브랜치와(하달의 이슈가 모두 허용되면) 통합 브랜치를 `push-branch`로 대상 저장소에 올리고, GitHub Actions가 연 이슈 PR·하달 PR의 CI 결과를 읽는다. CI 실패는 새 하달로 재작업한다(결정 8-32).
7. 끝 보고 하나에 이슈마다 상태·팀·하달·PR·CI와 "결정할 것"(트레인 승인, 거부목록, 막힘, 바꾼 기준)을 모아 묻는다. 사용자는 시작(애매함·계획 승인)과 끝 두 번만 본다(`coordinator-issue-flow`).
8. 사용자가 트레인을 승인하면 `run-train --handoffs <순서>`로 Actions의 머지 트레인을 시작한다(`main`은 Actions만 쓴다). 대상 원격·워크플로가 없으면 사용자 결정 뒤 `run-reflect`로 `main`에 반영하고 "CI 없음"을 적는다. 어느 쪽이든 앞 하달부터 한다: `--base`로 시작한 하달은 시작 지점 하달이 먼저다(어기면 스크립트가 거부한다).

## 6. 안전

- **훅이 막는다:** 쓰기는 지정 저장소 클론과 이슈만, 명령은 허용된 모양만(실행 문서의 "권한"), 하위 에이전트는 advisor만, 비밀값 파일 읽기 금지, PowerShell 도구 금지. 판정은 `harness/guard.mjs`, `harness/policy.mjs`.
- **세션 표지:** 앱이 Claude Code 안에서 띄워지면 세션 표지 변수를 지우고 넘긴다. 그렇지 않으면 대화 기록이 남지 않는다(ADR 0011).
- 지정 저장소가 공개면 쓰지 않는다. 사전 점검(`preflight.mjs`)과 설치(`setup.mjs`)가 비공개인지 확인한다.

## 7. 한계

- 폴더 신뢰 질문의 기본 선택이 No다. No면 허용 목록이 적용되지 않고, 상위 폴더가 신뢰돼 있지 않으면 훅도 돌지 않는다(Claude Code 문서, run-18 확인).
- 하달은 분리 실행이라, 하달 중 요구를 바꾸려면 하달을 멈추고 다시 말해야 한다. Esc로 턴을 끊어도 하달은 살아남고, 다음 턴에 `handoffs/last-wait.json`의 대기 번호로 이어 기다린다(run-18 h8에서 확인)(결정 8-21, 실행 문서 "턴이 끊긴 뒤").
- 컴팩션 뒤에는 훅(`SessionStart` compact, `harness/compact-notice.mjs`)이 알림을 넣고, 코디네이터가 보존 노트(`records/<프로젝트>-보존.md`)와 기록 문서를 다시 읽어 `컴팩션 복구: …` 한 줄로 보고한다(결정 8-20, run-18에서 확인). 보존 노트를 제때 쓰는지는 아직 길게 돌려 보지 않았다.
- 그 밖은 [known-limitations.md](known-limitations.md).
